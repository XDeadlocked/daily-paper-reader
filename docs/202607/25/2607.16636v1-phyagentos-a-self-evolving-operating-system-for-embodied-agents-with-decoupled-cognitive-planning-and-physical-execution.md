## 摘要
视觉-语言-动作模型、世界模型和智能体规划器各自推动了物理智能的发展，但它们的组合缺乏统一的执行抽象、共享状态、语义验证以及跨异构具身形态的持久经验。我们提出PhyAgentOS，一个运行时基础架构，将调度、验证、记忆、基准测试和安全作为系统级服务提供。其会话中心运行时将会话（而非动作）作为调度、兼容性预检、监督执行、证据收集和验收的最小单元。为了将认知与物理执行解耦，认知-物理边界采用文件系统：状态即文件协议将跨层状态具体化为带有YAML的Markdown格式，生成可检查、可版本化的记录，而无需Agent和运行时层之间的代码依赖。这些视图构成了统一的认知状态空间，对齐意图、能力、环境、执行和经验。会话验证器通过基于证据的成功、失败或重新规划的判定，区分执行终止与语义任务完成。验证结果通过认知记忆整合为可重用知识和纠正性经验，形成无需重新训练的试错循环。基准测试重用部署会话和验证路径，因此结果可追溯到真实执行。分层安全约束既限制策略驱动也限制智能体驱动的执行：预检、动作桥接、安全守卫、心跳监控以及目标局部约束。验证是渐进式的：游戏测试认知规划，仿真增加动力学和控制，真实机器人增加硬件噪声，同时保持认知层不变。PhyAgentOS在Optimus-67、StarDojo和DST-Dojo上进行基准测试，在19种以上的仿真和物理具身形态上验证，并在多个VLA模型上在LIBERO、Calvin和RoboCasa365上取得提升。

## Abstract
Vision-language-action models, world models, and agentic planners each advance physical intelligence, yet their composition lacks a common execution abstraction, shared state, semantic verification, and persistent experience across heterogeneous embodiments. We present PhyAgentOS, a runtime foundation delivering scheduling, verification, memory, benchmarking, and safety as system-level services. Its Session-Centered Runtime treats a session, not an action, as the minimum unit of scheduling, compatibility preflight, supervised execution, evidence collection, and acceptance. To decouple cognition from physical execution, the cognition-physics boundary is a file system: the State-as-a-File protocol materializes cross-layer state as Markdown with YAML, yielding inspectable, versionable records without code dependencies between Agent and Runtime layers. These views form a unified cognitive state space aligning intent, capabilities, environment, execution, and experience. The SessionVerifier distinguishes execution termination from semantic task completion via evidence-grounded verdicts of success, failure, or replan. Verified outcomes are consolidated through epistemic memory into reusable knowledge and corrective lessons, closing a trial-and-error loop without retraining. Benchmarking reuses the deployment session and verification path, so results trace to real execution. Layered safety constrains both policy-driven and agent-driven execution: preflight, action bridges, SafetyGuard, heartbeat monitoring, and target-local constraints. Validation is progressive: games test cognitive planning, simulation adds dynamics and control, real robots add hardware noise, with the cognitive layer held constant. PhyAgentOS is benchmarked on Optimus-67, StarDojo, and DST-Dojo, validated on 19+ simulated and physical embodiments, and gains on LIBERO, Calvin, and RoboCasa365 across multiple VLA models.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有具身智能系统（VLA模型、世界模型、智能体系统）各自解决部分问题，但组合时存在三大结构性缺陷：
  - 缺乏统一执行抽象与共享状态表示，层间接口碎片化。
  - 物理执行循环仅提供二进制完成信号，无语义反馈区分“执行终止”与“任务完成”，导致静默失败。
  - 缺乏跨会话持久记忆，知识无法累积，系统无法自我改进。
- **背景**：机器人操作系统（如ROS）主要提供通信中间件，而非具备调度、验证、记忆和安全等系统级服务的操作系统。当前架构将规划与执行紧耦合，难以移植和调试。
- **整体含义**：需要为物理智能提供一个操作系统层，将认知规划与物理执行解耦，并通过统一的协议、验证、记忆和安全机制实现可审计、可进化的闭环系统。

## 2. 方法论：核心思想、关键技术细节、算法流程
- **核心思想**：以会话（Session）为中心，将认知-物理边界设计为文件系统（State-as-a-File），通过人类可读的Markdown+YAML协议文件实现跨层状态具体化，使用SessionVerifier进行语义验收，并通过认知记忆驱动无需模型重训的自我进化。
- **关键技术细节**：
  - **状态即文件协议**：核心文件包括SESSIONS.md（会话事务）、SKILLRUNTIME.md（能力定义）、TARGETS.md（目标描述）、ENVIRONMENT.md（环境快照）、LESSONS.md（失败经验）、KNOWLEDGE.md（成功模式），及配置YAML文件（传感器、感知、运行时契约、安全）。
  - **会话中心运行时**：会话是最小调度、预检、监督、证据收集和验收单元。WatchdogSupervisor认领会话、执行兼容性预检、创建SessionRunner、监控心跳、写回结果。
  - **双执行流**：
    - 策略驱动流（PolicySkillRuntime）：连续控制策略（如VLA）通过PolicyAdapter标准化输入/输出，ActionBridge进行坐标转换、限幅等。
    - 智能体驱动流（BuiltinSkillRuntime）：智能体通过受控的TargetSessionHandle进行工具调用，动态决策。
  - **SessionVerifier**：将执行终止与语义完成分离。植入判断函数V(G, S0, ST, τ, H) → {success, failure, replan}，依据初始/终止状态、轨迹、历史输出三值判定，证据不可变。
  - **认知记忆闭环**：执行→验证→诊断→修正→重新验证→整合。成功模式存入KNOWLEDGE.md，失败纠正存入LESSONS.md，未来会话可通过ContextBuilder条件检索。
  - **分层安全架构**：五层防御：兼容性预检、ActionBridge、SafetyGuard（基于规则过滤非法命令）、心跳监控、目标局部约束（物理限位、紧急停止）。
- **算法流程（文字说明）**：
  1. Agent层：Goal Planner将自然语言目标分解，Goal Graph/Session Compiler编译依赖子任务，SkillRuntime/Target Selector绑定执行能力和目标，产生结构化会话（含目标、预条件、接受标准）。
  2. WatchdogSupervisor：从SESSIONS.md读取新会话，验证运行时-目标兼容性（包括适配器、工具清单），拒绝无效请求；创建SessionRunner并监控心跳。
  3. SessionRunner：协调策略/内置技能与目标，执行观察-推理-动作循环，收集观测、动作、事件等证据包。
  4. SessionVerifier：对比任务意图、初始/终止环境状态、执行轨迹，输出success（会话成功）、failure（会话失败，证据用于诊断）、或replan（生成子会话继续）。
  5. 失败经验通过诊断、修正、重新执行、验证后写入LESSONS.md/KNOWLEDGE.md，供未来检索。

## 9. 创新点总结
- **状态即文件（State-as-a-File）**：将物理世界状态抽象为人类可读的Markdown/YAML文件，实现认知-物理边界的统一、可审计、语言无关的具体化表示。

- **分层安全体系**：从请求预检、动作桥接、规则守卫、心跳监控到目标约束的五层防御，为物理智能提供OS级安全保障。
