## 摘要
视觉-语言-动作模型、世界模型和智能体规划器各自推动了物理智能的发展，但它们的组合缺乏跨异构具身形态的通用执行抽象、共享状态、语义验证和持久经验。我们提出了PhyAgentOS，一个运行时基础，提供调度、验证、记忆、基准测试和安全性作为系统级服务。其会话中心运行时将会话（而非动作）视为调度、兼容性预检、监督执行、证据收集和验收的最小单元。为了将认知与物理执行解耦，认知-物理边界是一个文件系统：状态即文件协议将跨层状态具体化为带有YAML的Markdown，生成可检查、可版本化的记录，且无需Agent层和Runtime层之间的代码依赖。这些视图构成了统一的认知状态空间，对齐意图、能力、环境、执行和经验。会话验证器通过基于证据的成功、失败或重新规划的裁决，区分执行终止与语义任务完成。验证结果通过认知记忆整合为可重用知识和纠正教训，无需重新训练即可关闭试错循环。基准测试重用部署会话和验证路径，使结果追溯到实际执行。分层安全性约束策略驱动和智能体驱动的执行：预检、动作桥接、安全守卫、心跳监控和目标局部约束。验证逐步进行：游戏测试认知规划，仿真增加动态和控制，真实机器人增加硬件噪声，同时保持认知层不变。PhyAgentOS在Optimus-67、StarDojo和DST-Dojo上进行了基准测试，在19+个仿真和物理具身形态上进行了验证，并在LIBERO、Calvin和RoboCasa365上跨多个VLA模型获得了提升。

## Abstract
Vision-language-action models, world models, and agentic planners each advance physical intelligence, yet their composition lacks a common execution abstraction, shared state, semantic verification, and persistent experience across heterogeneous embodiments. We present PhyAgentOS, a runtime foundation delivering scheduling, verification, memory, benchmarking, and safety as system-level services. Its Session-Centered Runtime treats a session, not an action, as the minimum unit of scheduling, compatibility preflight, supervised execution, evidence collection, and acceptance. To decouple cognition from physical execution, the cognition-physics boundary is a file system: the State-as-a-File protocol materializes cross-layer state as Markdown with YAML, yielding inspectable, versionable records without code dependencies between Agent and Runtime layers. These views form a unified cognitive state space aligning intent, capabilities, environment, execution, and experience. The SessionVerifier distinguishes execution termination from semantic task completion via evidence-grounded verdicts of success, failure, or replan. Verified outcomes are consolidated through epistemic memory into reusable knowledge and corrective lessons, closing a trial-and-error loop without retraining. Benchmarking reuses the deployment session and verification path, so results trace to real execution. Layered safety constrains both policy-driven and agent-driven execution: preflight, action bridges, SafetyGuard, heartbeat monitoring, and target-local constraints. Validation is progressive: games test cognitive planning, simulation adds dynamics and control, real robots add hardware noise, with the cognitive layer held constant. PhyAgentOS is benchmarked on Optimus-67, StarDojo, and DST-Dojo, validated on 19+ simulated and physical embodiments, and gains on LIBERO, Calvin, and RoboCasa365 across multiple VLA models.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现有具身智能体系统缺乏统一执行抽象、共享状态表示和语义验证机制。当机器人执行“抓取杯子”指令时，即使动作完成（轨迹达标、状态预测一致、工具调用无错误），杯子可能并未被抓起。执行终止与任务完成被混淆，控制器返回码被误判为目标达成证据。
- **背景**：视觉-语言-动作模型（VLA）、世界模型和智能体规划器三个范式各自解决了部分物理智能问题，但组成流水线后存在三类结构性失败：
  1. **抽象层级不匹配**：VLA处理像素输出关节轨迹，世界模型操作压缩隐状态，智能体规划器推理符号工具调用，三者无共享状态表示。
  2. **不透明性叠加**：十步计划中VLA调用、世界模型 rollout 交织，失败根因搜索空间过大（推理、工具调用、物理执行）。
  3. **缺乏持久记忆**：一次会话学到的知识在会话结束时被丢弃。
- **现有解决方案的不足**：ROS提供消息传递基础设施，但缺乏任务级调度、跨会话记忆、语义验证和统一安全架构。这些机制通常作为应用层临时构建，而非系统级服务。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：PhyAgentOS 是一个位于VLA、世界模型和智能体系统之下的操作系统层，将认知-物理边界视为文件系统而非函数调用接口。

### 关键技术细节

1. **State-as-a-File 协议**：
   - 所有跨进程数据（目标、技能、会话、观察、经验教训、知识）物化为人类可读的 Markdown 文件，内含 YAML 块。
   - 协议文档包括：
     - `SESSIONS.md`：会话中心（任务目标、选定的 Runtime 和目标、前提条件、验收标准、生命周期状态、执行结果）
     - `SKILLRUNTIME.md`：可重用执行方法（所需观察、动作形式、编排模式）
     - `TARGETS.md`：可用执行目标（类型、能力、观察模态、动作语义、端点信息、约束）
     - `ENVIRONMENT.md`：结构化环境快照（实体、属性、关系）
     - `LESSONS.md` / `KNOWLEDGE.md`：失败原因、纠正行动和成功模式
   - 辅以 `sensors.yaml`、`perception.yaml`、`runtime_contract.yaml`、`safety.yaml` 等配置。

2. **会话中心运行时（Session-Centered Runtime）**：
   - 会话（而非原子动作）是调度、预检、执行监控和事后验证的最小单元。
   - **WatchdogSupervisor**：唯一监督入口，声明待处理会话、验证运行时合同、创建 SessionRunner、监控心跳、传播超时/取消信号、写回最终结果。
   - **SessionRunner**：协调所选 SkillRuntime 和目标，管理观察-动作循环。
   - **PolicySkillRuntime**：持续控制策略（如VLA）的观察-推理-动作闭环，由运行时驱动低层循环。
   - **BuiltinSkillRuntime**：智能体在线工具循环（观察-决策-调用工具），通过受控的 TargetSessionHandle 进行。

3. **双执行流程**：
   - 策略驱动执行：`A_t = Policy(I, O_t, S_t, H_t)`
   - 智能体导向工具执行：`T_t = Agent(I, O_t, S_t, H_t)`
   - 两者共享相同会话、目标、监督和证据接口。

4. **会话验证器（SessionVerifier）**：
   - 区分执行终止与语义任务完成。
   - 判断函数 `V(G, S0, ST, τ, H) → {success, failure, replan}`，基于证据包（初始/终止观察、环境快照、动作历史、目标原生事件）进行裁决。
   - verdicts 触发状态转换：`success→succeeded`、`failure→failed`、`replan→replanned + child session`。

5. **闭环试错与经验整合（Epistemic Memory）**：
   - 六阶段循环：执行→验证→诊断→修订→重验证→整合。
   - 经验组织为三层：情节级（单体会话）、语义级（跨会话聚合）、方法论级（可推广的技能）。
   - `KNOWLEDGE.md` 存储验证过的成功模式；`LESSONS.md` 存储失败记录（含诊断和纠正效果）。

6. **分层安全架构**：
   - 兼容性预检（执行前验证组件组合有效性）
   - 动作桥接（坐标变换、单位归一化等确定性转换）
   - SafetyGuard（命令级验证：NaN拒绝、关节/工作空间限制、紧急停机）
   - 心跳监控（检测进程/网络故障）
   - 目标局部约束（机器人本地安全限制）

7. **基准测试作为自我演化工具**：
   - 使用与部署相同的会话、运行时、验证路径，确保指标可追溯到实际执行。
   - Availability Gate 验证仿真/策略可用性，Session Compiler 将任务-初始状态对编译为可重复会话。

## 6. 主要结论与发现

1. **统一协议基础设施**：State-as-a-File 协议使认知层与执行层解耦，实现语言无关、可审计、可版本化的执行记录。
2. **会话验证器价值**：区分执行终止与任务完成，通过证据裁决避免“静默失败”，在仿真任务中将多个VLA模型的成功率提升 +0.4至+9.2个百分点（绝对）。
3. **认知记忆闭环**：无需神经网络重训练，通过 `LESSONS.md` 和 `KNOWLEDGE.md` 积累经验，使游戏层生存天数翻倍（Don't Starve: 1.02→2.10天），30%突破Day 3。
4. **渐进式验证**：同一认知层可驱动游戏引擎、仿真和真实机器人，游戏层表现可预测物理层行为。
5. **模型无关性**：PhyAgentOS 对 OpenVLA、π0、π0.5、X-VLA、RLDX-1、WorldDreamer 等不同策略后端均产生一致提升。

## 7. 优点

1. **架构创新**：将认知-物理边界设计为文件系统，实现清晰解耦；会话作为运行时最小单元提供生命周期管理。
2. **语义验证替代二进制信号**：SessionVerifier 基于证据区分“动作完成”与“任务达成”，是具身系统可靠性关键改进。
3. **自我演化不依赖重训练**：Epistemic Memory 使系统积累经验，跨会话、跨任务、跨具身形态复用，降低全栈更新成本。
4. **渐进式验证范式**：游戏→仿真→实际机器人逐步增加物理复杂度，允许隔离认知缺陷与物理缺陷，适合团队分工迭代。
5. **标准化基准测试**：基准测试使用与部署相同的运行时路径，确保指标可追溯、可重复，支持自我演化有效性验证。
6. **分层安全**：五层防御（预检、桥接、SafetyGuard、心跳、局部约束）提供纵深防御，安全事件可写回认知状态供后续分析。

## 8. 不足与局限

1. **轮询协议延迟**：当前实现使用轮询，引入与轮询间隔成比例延迟（尤其对实时响应要求高的真实机器人）。文中提到事件驱动方案可降低延迟但需保证原子写一致性。
