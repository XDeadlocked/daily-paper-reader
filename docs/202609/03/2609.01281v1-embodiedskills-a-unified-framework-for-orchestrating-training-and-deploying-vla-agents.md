## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射为机器人动作，但长程任务需要的不仅仅是动作预测。智能体必须随着物理状态的变化协调感知、规划、执行、进度验证和恢复。动作预测或模型生成的技能决策本身，并不能保证所提议的操作在当前状态下是有效的，也不能保证其结果会被验证。我们提出EmbodiedSkills，一个统一框架，将每个技能决策视为一个执行提议：运行时在执行前检查其前置条件，并在执行后验证结果。一个共享的可执行技能接口在单个智能体循环中连接高层技能选择、受限的低层VLA执行和动作后验证。由于该接口保持不变，低层VLA策略可以被替换或调整，而无需改变智能体循环。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，这些轨迹为各个组件提供监督，并在交互反馈可用时支持可选的在线适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化了EmbodiedSkills。任务适应的低层VLA策略在50个RoboTwin 2.0任务中实现了86.20%的平均成功率，在四个LIBERO套件中实现了97.40%的平均成功率。这些结果确立了EmbodiedSkills中使用的任务适应的低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务适应执行方法实现了12.5%的平均成功率。该框架提供了一个可训练和可检查的智能体层，用于将这些策略转化为闭环的具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 2. 论文提出的方法论

### 2.1 核心思想

- **技能即执行提议（Skill-as-Execution-Proposal）**：框架将每一次技能决策视为一个"执行提议"，由独立的**运行时（runtime）机制**在执行前校验其前置条件，并在执行后对输出进行验证。
- **策略与运行时分离（Policy–Runtime Separation）**：高层 VLM 策略（如 Qwen3-VL）只负责提出结构化的技能决策，而受保护的有状态运行时负责强制校验阶段兼容性、输入的必需品、工件（artifact）新鲜度、动作合法性与状态迁移合法性，从而防止无效决策被静默转化为物理动作，并使错误显式化、可诊断。
- **共享技能接口（Shared Skill Interface）**：一个固定的可执行技能契约连通高层技能选择、受限的低层 VLA 执行（bounded low-level execution）和动作后验证，使低层策略可被灵活替换或适配而不影响整个智能体循环。

### 2.2 关键技术与机制细节

- **智能体状态表示**（公式1、2）：每步状态记为 $s_t = (z_t, M_t, H_t)$，其中 $z_t$ 为当前阶段（phase），$M_t$ 为任务工件集合（当前观察、感知/绑定结果、世界状态、任务计划、活动子目标、预检证据、动作块、执行报告、验证报告与恢复上下文等），$H_t$ 为有序循环轨迹。
- **三种高层决策**（公式3、4）：策略输出 $\pi_\theta(\cdot \mid C_t, z_t, \mathcal{A}_t)$ 中的决策 $d_t$ 分为三种控制类型：
  - `RunSkill(k, q)`：执行特定技能；
  - `AdvanceStage`：阶段前进；
  - `FinishRun`：终止运行。
- **可执行的技能契约**（公式5）：每个具身技能定义为 $k = (X_k, Y_k, \text{pre}_k, \text{exec}_k, \text{post}_k, \text{fail}_k)$，即带类型的输入/输出模式、前置条件、可执行操作、结果状态更新和失败映射。该契约保证"文本提议"必须经校验后才能成为物理状态变迁，且工件带有来源与新鲜度元数据，在依赖变化时可自动失效，防止陈旧预测授权新动作。
- **六阶段受保护状态机**（表1、公式6）：
  - 阶段序列为 `观察（Observe）→ 规划（Plan）→ 预检（Preflight）→ 执行（Execute）→ 验证（Verify）→ 恢复（Recover）`；
  - 注意这并非固定单向流水线：策略可依据更新后的证据回访更早阶段（重观察、重规划等）；
  - 每个技能类型都可归属于某一 Phases，运行时确认各操作的证据有效性。
- **守卫的运行时迁移机制**（公式7—10）：

- **有界动作执行**（公式11—13）：在 Execute 阶段，将当前子目标 $g_t$、观察 $O_t$、机器状态与预检证据输入低层 VLA 策略，得到动作块 $a_t$。动作块需满足：行动类型合法、维度有效、执行范围 $0 < H_t ≤ H_{max}$、且与当前子目标/观察一致（fresh），否则不会被接受执行。
- **验证与恢复**（公式14）：验证阶段只评估当前活跃子目标，根据执行后的新证据预测语义路由，包括继续（Continue）、前进（Advance）、重观察（Reobserve）、重规划（Replan）、恢复（Recover）或结束（Finish）。

## 6. 论文的主要结论与发现

1. **闭环结构显著优于开环执行**：在相同动作预算下，缺少中间验证、语义子目标分解或多块重试均造成大幅性能下降，证明长程任务必须"执行—检查—继续/修正"，而不能依赖固定预算的一次性执行。
2. **策略/运行时分离是构建可靠智能体的关键**：把高层提议与运行时的前置校验/后果验证分开，可使失败显式化、轨迹可追踪，并在不修改 AgentLoop 的情况下替换或更新底层 VLA 策略。
3. **共享技能接口支持跨基准迁移**：同一套 subgoal 条件化执行接口可同时适配 RoboTwin 2.0（81 种双任务子场景）与 LIBERO，说明其不绑定特定任务体系。
4. **组件级监督轨迹是有效的训练范式**：在冻结底层策略的条件下，高层调度器、规划器和验证器可通过接口一致的轨迹独立训练与升级。
5. **存在明显的性能天花板**：在依赖记忆交互的 RMBench 场景，当前任务的子目标条件化执行方式成功率仅 12.5%，说明仅在子目标层做条件化仍不足以处理需要完整历史状态记忆的任务。

## 7. 优点与亮点

- **概念创新**：提出"执行契约/技能契约+运行时守卫"的架构，将策略组合与执行安全显式解耦，是对先前将技能仅作为规划词汇或模型内部拆分做法的重要补充。
- **工程与操作性兼顾**：给出了紧凑智能体上下文、历史压缩策略、工件新鲜度与依赖无效机制、具体可部署在有真实物理环境中的闭环循环（伪代码清晰）。
- **模块化与可扩展性好**：规划、验证、调度、VLA 策略和低层环境适配器均可在统一接口下替换、独立微调或做在线优化；不强制要求所有组件采用同一种内部表达或联合训练。
- **实验覆盖相对全面**：50 任务细粒度对比、多基准（RoboTwin 2.0 / LIBERO 四套件 / RMBench 特殊场景）和精细消融（+38.0/+51.8/+66.7 个百分点的影响分解）共同支撑框架设计动机。
- **训练与部署一致性**：强调"部署一致性采样"和接口统一，避免训练/推理不符造成的性能高估。

## 8. 不足与局限

- **算术与保密性缺陷**：
  - 全文未报告任何算力数据（GPU 数量/型号/训练时长），无法评估资源门槛；
  - 多数基线数值依赖外部文献（LingBot-VA 与 RMBench/OpenPI 论文），未有同代码同环境的重测，存在跨环境比较偏差风险。
- **特殊任务的局限**：
  - RMBench 记忆依赖任务成功率仅 12.5%，虽然优于基线但绝对值很低，说明框架的对于"任务历史信息利用"尚未形成可靠方案；也未在真实机器人上部署验证，仅限于仿真平台（在 LIBERO 与实际物理环境仍存在 sim-to-real 距离）。
- **架构本身的限制（作者自述+推断）**：
  - 依赖任务特化专家策略，若实现为 50 个单任务微调模型，则训练、存储与部署成本高；
  - 多次 VLM 调用和动作后观察引入额外延迟，实时性受限；
  - 显式契约只能阻止非法状态转移，无法保证语义合理的模型决策真的能导致正确物理状态；在物体遮挡、视觉模糊或进度不可观测时验证仍有失效风险；
  - 子目标级的错误定位或错误接地可以"合法地"通过模式检查但产生错误动作；长时程任务中低层规划/执行误差会逐步累积，增加模型调用次数与重试次数。
- **评估局限**：缺少对超参与运行开销（time cost per task）、失败类型学（failure taxonomy）和在线适应效果的量化报告，也未对社会中更真实的"即用型"通用策略与专家策略做多种体系结构的泛化验证；在 RoboTwin 2.0 的对比中，"Ours"的优越性可能来自任务特化数据的充分微调，而非框架本身的推理调度优势，这一贡献归属需要更严谨的对照控制来区分。
