## 摘要
视觉-语言-动作（VLA）模型表现出强大的语义理解能力，但在部署过程中仍会出现系统性失败。这些失败发生的条件，以及是否可以在不重新训练的情况下进行校正，目前仍知之甚少。在本文中，我们朝着解决这一差距迈出了步伐。我们提出了CorrectVLA框架，该框架将任务级别的自然语言校正转化为加性的动作幅度调整，而无需修改策略权重。人类提供单一的任务级别校正，统一应用于所有 rollout，无需每回合干预。在仿真中，CorrectVLA在分布内和分布外任务中均恢复了执行错位失败。在环境变化下的UFactory xArm7真实机器人实验中，CorrectVLA在基础策略几乎完全失效的情况下恢复了接近完美的成功率，并泛化到不同的物体位置和身份。通过对LIBERO-90上失败模式的分类，我们发现执行错位失败（即策略到达正确目标但动作幅度校准错误）是可校正的子集，而其他语义理解本身崩溃的失败模式则不适用于该方法。当策略具备策略正确性时该方法成功，而当基本理解缺失时则失败，这为推理时校正建立了一个实用的操作边界。

## Abstract
Vision-Language-Action (VLA) models demonstrate strong semantic understanding yet exhibit systematic failures during deployment. The conditions under which these failures occur, and whether they can be corrected without retraining, remain poorly understood. In this paper, we take steps toward addressing this gap. We present CorrectVLA, a framework that translates task-level natural language corrections into additive action magnitude adjustments without modifying policy weights. A human provides a single task-level correction, applied uniformly across all rollouts without per-episode intervention. In simulation, CorrectVLA recovers execution misalignment failures across both in-distribution and OOD tasks. In real-robot experiments on a UFactory xArm7 under environment shift, CorrectVLA restores near-perfect success where the base policy almost entirely breaks down, generalizing across object locations and identities. Through a taxonomy of failure modes on LIBERO-90, we find that execution misalignment failures, where the policy reaches the correct target but miscalibrates action magnitudes, represent the correctable subset, while other failure modes where semantic comprehension itself breaks down are not amenable to this approach. The approach succeeds when policies possess strategic correctness and fails when fundamental comprehension is absent, establishing a practical operational boundary for inference-time correction.

## 2. 方法论：CorrectVLA

- **核心思想**：将任务级自然语言纠正映射为**加性的、按维度、按时间窗口分布的动作幅度调整**（additive action magnitude adjustments），叠加到冻结策略的输出上，不更新任何策略权重。
- **阶段 A —— 结构化参数提取**：利用 LLM 从人类反馈中提取四个结构化参数：动作维度 `dk`（如 x/y/z/roll/pitch/yaw/gripper）、方向 `sk`（+1/-1）、幅度词 `mk`（"slightly/more/much"）、时间窗口 `[t_start, t_end]`，得到结构化纠正 `ck = (dk, sk, mk, t_start,k, t_end,k)`。
- **阶段 B —— 幅度量化**：将自然语言幅度词映射为数值范围（"slightly"→[0.3,0.5]，"more"→[0.5,0.8]，"much"→[0.8,1.0]），由 LLM 在范围内取值并结合方向得到有符号权重 `wk ∈ [-1.0, 1.0]`。
- **阶段 C —— 时间分布**：构造分段线性包络函数（式 1），在指定时间窗口内从 0 线性上升至峰值再回落至 0，确保纠正在时间上平滑且局部化，窗口外零影响。
- **完整组合**（式 2-3）：多个纠正实例按维度叠加，形成密集的逐时刻、逐维度修正量 `δd(t)`，叠加到原始动作上得到修正后的动作 `a_corrected = a + δ`。
- **关键特性**：稀疏反馈、权重冻结、任务级单次修正（统一应用于所有 rollout）、无需逐回合介入。

## 6. 主要结论与发现

- **失败模式分类学**：在 LIBERO-90 上的 133 个任务-模型评估中，VLA 策略的部署失败可归为四种一致模式——任务误解（≈47%/50%）、感知失败（≈25%/22%）、执行错位（≈23%/22%）、多步规划（≈5%/6%）。该分布在两个架构不同的模型间高度一致，暗示这是 VLA 在分布偏移下的共性特征。
- **可纠正性边界**：只有**执行错位失败**（策略到达正确目标但动作幅度校准错误）适用于推理时修正；其余模式源于基本语义理解的崩溃，非幅度调整所能弥补。
- **仿真恢复效果**：分布内恢复率 46.8%（65/139，总体成功率从 93.0% 提升至 96.3%）；分布外恢复率 10.1%（33/328，总体成功率从 27.1% 提升至 34.4%）。
- **真实机器人效果**：机器人基座位置迁移后 π0.5 成功率从 95%（19/20）骤降至 10%（2/20）；应用单次任务级修正后恢复到 95%（19/20），且在异位、异物体条件下均有效。
- **LLM Baseline 全面失败**：纯视觉自动修正无法可靠估计幅度，所有条件下恢复率为 0，验证了人工反馈不可替代性。
- **总体原则**：部署时应先诊断失败模式，识别"策略正确但执行失准"的情形，再施加最小充分的干预；修正成功的充要条件是策略具备基本语义正确性。

## 7. 优点

- **问题定位精准**：将"理解任务语义"与"校准执行幅度"分离，提供了一个清晰、可操作的干预边界。
- **方法简洁有效**：三阶段流水线（结构化提取 → 幅度量化 → 时间分布）简洁、可解释、易于部署，不依赖训练基础设施。
- **训练免费**：全程权重冻结，单次任务级修正统一应用于所有 rollout，避免了逐回合干预的高人工成本。
- **时间稀疏性洞见**：通过任务级语言修正的局部时间窗口设计，精准作用于轨迹瓶颈，验证了 VLA 执行中语义与运动可控分离的"组合性"。
- **实验设计严谨**：同时纳入仿真与真实机器人、两种 VLA 架构、三个泛化条件，并设置纯自动修正的 LLM baseline 作为对照，排除了"无需人类即可自动纠正"的替代解释。
- **失败分类学具有通用价值**：跨模型一致的失败分布为后续研究部署时适配提供了重要参考框架。

## 8. 不足与局限

- **幅度量化不确定性**：从自然语言到数值的映射基于经验预设范围，存在偏差风险，可能需要多轮修正才能收敛；论文未量化该不确定性。
- **单一修正假设**：任务级单次修正假设同一任务内存在一个主导性失败模式；若失败模式在回合间差异较大，单一修正难以泛化到所有 rollout。
- **分类学源于仿真**：LIBERO-90 上的失败模式分布是否适用于真实世界部署场景，尚未验证；真实环境中的失败分布可能不同。
- **真实实验范围有限**：仅在单一任务类型（pick-and-place）及单一基座策略（π0.5-DROID）上验证，缺乏多任务、多物体的系统性支撑；不同物体条件下的成功率（80%）低于同物体条件（100%），泛化边界仍待探索。
- **对底座的依赖**：方法成立的前提是策略具备基本语义正确性；在最困难的语义失败场景下天然失效，适用面受限。
- **缺少与更多替代方法的系统对比**：未与 ITPS、FOREWARN 等测试时引导方法在实际改正率上做对比，也未进行组件级消融分析。
- **LLM 成本与延迟未讨论**：未报告 LLM 推理延迟和 API 成本，对真实部署可行性有一定影响。
