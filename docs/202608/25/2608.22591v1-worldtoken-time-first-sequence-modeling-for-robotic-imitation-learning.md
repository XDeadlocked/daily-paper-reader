## 摘要
机器人策略在每个决策步骤接收异构观测，但序列模型在如何随时间组织这些输入方面存在差异。我们提出WorldToken，一种时间优先的策略实例化，将每个策略时间步内的多视角图像、本体感觉和任务条件融合为一个世界令牌。一个因果时间Transformer对生成的世界令牌序列进行建模，扩散动作头生成动作块。在23个RoboCasa任务中，一个85.3M参数的策略（除冻结的预训练CLIP文本编码器外从头训练）在每任务使用2,900个生成演示的情况下，实现了59.45%的平均闭环成功率。对五个数据集规模、五个模型规模和两个训练种子进行的完整因子扫描显示，增加目标域数据能带来一致收益，而超过中等模型规模后收益递减。在相同检查点历史截断下，将可见历史减少到一或两个策略时间步会降低所有50个RoboCasa策略的闭环成功率。在RMBench Blocks Ranking上，将可见历史从146秒减少到8秒会使评估器成功率从95%降至28%，而探索性扩展滚动则能维持参考交换序列超过850秒。这些结果确立了完整WorldToken实例化的实证可行性，并刻画了其在所测试方案下的数据扩展和时间上下文行为。它们并未确立相对于其他序列组织的优越性，也未分离完整实现中哪些组件驱动了所观察到的性能。

## Abstract
Robot policies receive heterogeneous observations at each decision step, yet sequence models differ in how they organize these inputs over time. We introduce WorldToken, a time-first policy instantiation that fuses multiview images, proprioception, and task conditioning within each policy timestep into one world token. A causal temporal Transformer models the resulting world-token sequence, and a diffusion action head generates action chunks. On 23 RoboCasa tasks, an 85.3M-parameter policy trained from scratch apart from a frozen pretrained CLIP text encoder achieves 59.45% mean closed-loop success using 2,900 generated demonstrations per task. A complete factorial sweep over five dataset sizes, five model sizes, and two training seeds shows consistent gains from additional target-domain data and diminishing returns beyond moderate model size. Under same-checkpoint history truncation, reducing visible history to one or two policy timesteps lowers closed-loop success for all 50 RoboCasa policies. On RMBench Blocks Ranking, reducing visible history from 146 to 8 seconds lowers evaluator success from 95% to 28%, while an exploratory extended rollout sustains the reference swap sequence for over 850 seconds. These results establish the empirical feasibility of the complete WorldToken instantiation and characterize its data-scaling and temporal-context behavior under the tested recipes. They do not establish superiority over alternative sequence organizations or isolate which components of the complete implementation drive the observed performance.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：机器人策略的每步决策都接收多模态异构观测（多视角图像、本体感觉、语言指令等），但现有序列模型在“如何定义序列的基本单元”这一根本问题上没有统一答案。不同的序列组织方式（如将每个时间步拆成多个模态 token、使用循环模块、显式记忆或检索机制）会显著影响多模态编码、时间上下文建模和动作生成之间的接口。
- **灵感来源**：语言模型中，文本 token 是基本序列单元；物理世界中，物理时间是一个天然的组织轴。作者提出“时间优先”（time-first）组织原则：**每个策略时间步内先解决异构观测的融合，产生一个世界 token，再在顶层按物理时间排列成因果序列**。
- **整体含义**：论文不是要宣称 WorldToken 优于所有替代方案，而是将其作为**一种可解释、可干预的具身序列建模接口**，系统研究其可行性、数据/模型规模行为以及时间上下文的使用方式。

## 2. 方法论：核心思想、关键技术细节、公式与流程

### 2.1 总体框架
- 策略分解为三个顺序模块：
  - 多模态编码器 `Eθ`：将当前观测 `o_t` 压缩为一个世界 token `z_t`
  - 因果时间 Transformer `Tϕ`：对历史世界 token 序列 `z≤t` 进行因果建模，得到历史条件表示 `h_t`
  - 扩散动作解码器 `Dψ`：基于 `h_t` 生成 H 步动作块 `A_t`
- 形式化：`z_t = Eθ(o_t)`, `h_t = Tϕ(z≤t)`, `A_t ~ Dψ(·|h_t)`

### 2.2 世界 token 的构建（多模态编码器）
- 每个相机视图经过视觉 stem（CNN）得到 patch tokens，所有视觉特征投影到模型宽度，并加入空间位置、视角和模态嵌入。
- 本体感觉和任务条件分别投影为 token，与视觉 token 拼接成每步的模态内序列。
- 加入 4 个可学习的读取 token（readout tokens）：观测 token 不能注意读取 token，而读取 token 可以注意所有 token，从而在不干扰观测表示的情况下完成信息聚合。
- 最终将 4 个读取 token 的输出拼接，经 RMSNorm 和线性投影，得到该时间步唯一的**世界 token** `z_t`。

### 2.3 因果时间 Transformer
- 基于 Qwen2 解码器架构，从零初始化，对世界 token 轨迹进行因果自注意力。
- 使用 1D RoPE 编码策略时间；`h_t` 只依赖于 `z≤t`。
- 默认上下文长度 `C=10`；当序列超过上下文窗口时，最早 token 被丢弃，且由于 RoPE 相对位置不变，滑动窗口不会引入额外位置偏差。

### 2.4 扩散动作头
- 动作块 `A_t` 维度为 `H × da`（H=10，da=12），动作归一化到 [-1,1]。
- 训练时使用 DDPM 前向加噪，DiT 去噪器以 `h_t` 和扩散步 `k` 为条件，通过 adaLN-Zero 调制预测噪声。
- 推理时采用随机 DDPM 采样生成动作块，但只执行前 `Hexec=4` 步，然后重新观测、追加世界 token 并重新规划（receding-horizon 控制）。

### 2.5 关键设计差异
- **“每个时间步一个 token”** 仅约束时序表示，不限制模态内编码复杂度。
- 执行的动作不插入序列，其效果通过后续图像和本体感觉间接反映。
- 默认只监督动作生成，不进行未来观测预测（但未来可以扩展）。

## 6. 主要结论与发现

1. **有效性**：在 23 个 RoboCasa 任务、每任务 2900 条生成演示下，85.3M 参数模型（除冻结 CLIP 文本编码器外全部从零训练）达到约 **59.45% 平均闭环成功率**，最好单次评估 62.0%（218.8M 模型）。这一水平进入 billion-scale 预训练系统的报告范围（约 50–79%）。
2. **数据扩展**：在全部 40 个相邻数据集规模比较中，增加数据总是降低 holdout RMSE 并提高闭环成功率；从 D=50 到 D=2900，RMSE 下降 47.0–56.8%，SR 提高 32.7–39.3 个百分点。RMSE 随数据量服从幂律（指数 0.151–0.211，R²≥0.99）。
3. **模型容量扩展**：容量从 44.3M 增加到 218.8M 稳定降低 RMSE，但超过 218.8M 后无一致收益；闭环成功率对容量的趋势较弱。数据与容量存在交互：数据量越大，中等容量区间的收益越明显。
4. **时间上下文使用**：同检查点截断历史（1 或 2 个可见步）使所有 50 个 RoboCasa 策略成功率下降；但单独训练短上下文策略可恢复大部分损失，说明大部分历史依赖是训练上下文适应，而非任务不可约条件。在 RoboCasa 上，约 5 个可见步已捕获大部分收益。
5. **长时间上下文与有序行为**：在 Blocks Ranking 上，可见历史从 608 个 token 降到 32 个 token 时，评估器成功率从 95% 降至 28%，失败集中在需要多次顺序交换的场景；而扩展滚动中一条轨迹完成 31 次正确交换（超过 850 秒），远超演示边界（≤5 交换）和单个上下文窗口（145.9 秒），表明策略学到了可重复的三交换周期。
6. **离线拟合与闭环成功的关系**：RMSE 和 SR 在大尺度上共同改进，但相邻策略之间可能背离（如更长训练上下文改善 RMSE 但不改善 SR），因此二者是互补指标，不能互相替代。

## 7. 优点（方法与实验设计亮点）

- **时间优先接口的可解释性**：以策略时间步为基本序列单元，使得时间上下文长度直接等于策略决策次数，不随模态 token 数量变化，便于在固定接口下进行受控归因。
- **大规模的因子扫描**：完整 5×5×2 数据×容量×种子扫描，系统刻画了目标域数据与模型容量的扩展行为，并揭示了容量收益随数据量变化的交互模式。
- **严格受控的上下文干预**：同检查点截断、短上下文训练、Blocks Ranking 历史长度变化，都保持权重、初始条件、评估协议固定，能够区分“历史利用率”和“任务固有需求”。
- **诚实且透明的报告**：作者明确区分恢复状态（recovered-exact / repair-log / archived-only），不隐瞒数据丢失事件；不夸大多个组件的贡献，明确说明未与替代组织的公平对比。
- **从零训练即可达到强基线**：仅使用冻结 CLIP 文本编码器，视觉和策略部分全部从随机初始化训练，避免了大规模预训练依赖，证明了目标域数据足以支撑较强性能。

## 8. 不足与局限

- **实验范围有限**：所有实验均在仿真中进行（RoboCasa、RMBench），没有真实机器人验证；仅做动作模仿学习，不包含预测目标、显式动作历史或主动感知。
- **缺乏与替代序列组织的公平比较**：论文未在完全匹配条件下与 RT-1、ICRT、GR-1、Diffusion Policy 等不同序列组织方式对比，因此不能证明时间优先组织具有性能优势。
- **组件归因不完整**：完整实现包含多模态编码、时间骨干、扩散解码等多个模块，实验未隔离每个组件的独立贡献，无法确定是哪一个部分驱动了性能。
- **单任务长时间上下文证据**：扩展上下文效益的结论主要集中在单个 Blocks Ranking 任务上，虽然压力测试有趣，但通用性存疑。
- **部分消融实验统计力不足**：token 粒度、动作分布、视觉宽度等诊断仅使用单个种子，且没有进行完整的规模分析，不能给出稳健的结构性结论。
- **上下文窗口滑动机制**：虽然 RoPE 的相对位置设计使得滑窗无绝对位置偏差，但未对超长序列的记忆压缩或检索进行系统研究。
- **超参数选择受一次性校准限制**：学习率表在冻结前只经过短期 D=300 校准，且校准滚动的执行变异性较大；作者承认这些选择不是统计上严格的全局最优。
- **结果恢复状态带来的不确定性**：原始服务器被入侵导致部分指标以“归档记录”而非完整可重算数据为基础（如某个 1.49B 端点 RMSE、部分标准损失诊断），虽然作者标注了恢复状态，但对完全独立复现仍构成挑战。
- **未测量系统级效率**：没有报告端到端延迟、显

存占用、吞吐量或推理延迟等系统级效率指标，也没有与替代架构的端到端成本对比，因此难以判断其在真实机器人部署中的实时性与资源需求是否具有优势。

## 9. 总结与展望

- **总体定位**：WorldToken 不是一个追求 SOTA 性能的“大模型”方案，而是一个试图为具身智能序列建模提供统一接口的设计研究。它用“一个时间步一个 token”的简洁原则，把多模态融合、历史建模和动作生成三个子问题解耦，使得数据规模、模型容量、上下文长度等因素可以被独立且受控地研究。
- **核心贡献的持久价值**：作者以大规模的受控实验证明，即使从零开始训练（仅冻结文本编码器），在中等规模仿真任务上也能逼近十亿级预训练模型的闭环成功率；更重要的是，通过同检查点上下文截断和短上下文再训练两组对照，首次区分了“模型对上下文的利用能力”与“任务对上下文的固有需求”，这一方法论比具体数字更有参考意义。
- **局限性的启示**：由于缺乏与 RT-1、GR-1、Diffusion Policy 等替代序列组织的同条件对比，以及缺少真实机器人验证，时间优先组织是否优于其他方案仍无定论；未来工作可在统一评估协议下比较不同 token 化策略，或将 WorldToken 扩展到多机器人、多传感器融合和长时程操作场景。
- **对后续研究的建议**：可沿三条线推进——(1) 将世界 token 同时用于预测与动作（世界模型化），检验预测目标是否能提升时间上下文利用率；(2) 在统一代码库中公平对比其他序列组织方式，明确时间优先接口的性能边界；(3) 在真实机器人上验证滑窗上下文与 receding-horizon 控制在部署中的鲁棒性。
- **最终评价**：这是一项实验严谨、报告透明、方法论贡献大于性能贡献的研究。它的“时间优先”思想简洁而有说服力，其规模扫描和上下文干预实验为具身模仿学习提供了难得的实证参照，尽管尚不构成完备的通用解法，但为后续建立在物理时间轴上的策略序列建模奠定了坚实基础。
