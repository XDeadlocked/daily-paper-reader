## 摘要
空中视觉语言导航（VLN）要求具身智能体随时间整合视觉证据、规划未来动作，并在部分可观测条件下判断是否已到达导航目标。尽管近期视觉-语言-动作（VLA）模型提供了一种有前景的感知到动作范式，但由于历史上下文有限、规划时域短以及隐式终止不可靠，将其应用于空中导航仍具挑战性。为应对这些挑战，我们提出DreamFly，一种基于Dream-VLA的扩散式空中VLN框架。DreamFly引入因果对齐的历史记忆，仅利用当前决策步骤之前的观测来增强当前视觉表征，从而在无未来信息泄漏的情况下实现时间推理。我们进一步将导航建模为后退时域扩散规划，其中策略预测一个K步动作块，但仅执行第一个动作后重新规划。这种“规划K步、执行一步”策略利用未来动作作为辅助规划目标，同时保持闭环视觉反馈。最后，LiteStop在初始全掩蔽状态下直接根据动作logits估计停止概率，将显式终止与动作生成解耦。在OpenFly基准上的实验表明，在未见与可见环境中均有一致改进。DreamFly在test-seen/test-unseen分割上分别达到32.04%/29.46%的SR和28.22%/23.54%的SPL，在两个指标上均优于所有对比方法，同时实现最低导航误差。这些结果证明了联合建模历史上下文、未来动作结构和显式终止对于空中VLN的有效性。

## Abstract
Aerial vision-language navigation (VLN) requires an embodied agent to integrate visual evidence over time, plan future actions, and determine when it has reached a navigation goal under partial observability. Although recent VLA models offer a promising perception-to-action paradigm, adapting them to aerial navigation remains challenging due to limited historical context, short planning horizons, and unreliable implicit termination. To address these challenges, we propose DreamFly, a diffusion-based aerial VLN framework built on Dream-VLA. DreamFly introduces a causally aligned historical memory that augments the current visual representation using only observations preceding the current decision step, enabling temporal reasoning without future information leakage. We further formulate navigation as receding-horizon diffusion planning, where the policy predicts a $K$-step action chunk but executes only the first action before replanning. This plan-$K$, execute-one strategy uses future actions as auxiliary planning targets while preserving closed-loop visual feedback. Finally, LiteStop estimates the stop probability directly from action logits at the initial all-mask state, decoupling explicit termination from action generation. Experiments on the OpenFly benchmark demonstrate consistent improvements in seen and unseen environments. DreamFly achieves 32.04%/29.46% SR and 28.22%/23.54% SPL on the test-seen/test-unseen splits, respectively, outperforming all compared methods on both metrics while attaining the lowest navigation error. These results demonstrate the effectiveness of jointly modeling historical context, future action structure, and explicit termination for aerial VLN.

## 1. 核心问题与整体含义（研究动机与背景）

- **任务背景**：空中视觉语言导航（Aerial VLN）要求无人机（UAV）在大型 3D 环境中，依据自然语言指令和连续获取的视觉观测，自主导航到指定目标。与地面 VLN 不同，空中导航需同时协调水平位移、垂直运动与视角调整，且城市环境的遮挡与大尺度特性决定了单个第一视角观测只能覆盖局部场景。
- **核心挑战**：现有 VLA（视觉-语言-动作）模型虽然提供了感知到动作的端到端范式，但直接迁移到空中导航面临三个关键问题：
  - **历史上下文不足**：仅依赖当前观测的策略容易丢失此前出现、但已离开视野的地标信息。
  - **规划时域过短**：单步动作预测缺乏前瞻性，难以捕捉短时域内的动作结构与依赖关系。
  - **终止判断不可靠**：隐式地将"停止"与普通动作同等生成，忽略了过早停止会不可逆地结束导航回合这一不对称风险。
- **整体思路**：论文主张在一个统一的闭环决策过程中，显式地协调**历史信息**、**未来动作规划**与**终止判定**三个时间维度，以提升空中 VLN 的导航成功率和泛化能力。

## 2. 提出的方法论：核心思想与技术细节

DreamFly 以 Dream-VLA 作为骨干模型（因其双向扩散结构天然支持动作块并行预测），提出三大核心组件：

### 2.1 因果对齐的历史记忆（Causally Aligned Historical Memory）

- **因果时间边界**：在决策步骤 t，历史记忆 M<t 仅包含在 t 之前获取的观测 (Oτ)τ<t，采用"先读后写"（read-before-write）协议，当前观测的信息只能从后续决策开始进入历史分支，从而防止未来/当前信息泄漏到历史表征中。
- **候选构建**：利用冻结的 CLIPSeg 密集路由器和 OWLv2 区域路由器，以完整导航指令为条件提取视觉候选；OWLv2 区域直接映射到 CLIPSeg 特征空间，候选间通过空间重叠和视觉相似度进行合并。
- **长期记忆槽**：通过候选与活动轨迹的视觉/空间一致性累积跨观测证据；被持续支持的候选可提升为长期记忆（含锚点特征和原型特征），单次观测的高置信候选也能通过单次提升进入记忆。记忆为 16 个固定容量的槽，每个槽记录锚点特征、原型特征、原型存在标志和最近更新步数。
- **门控交叉注意力融合**：以当前图像 token 为查询、历史记忆槽为键值进行掩码交叉注意力（按槽有效性屏蔽无效槽），再通过零初始化的门控残差连接将检索到的历史上下文融入当前视觉表征。初始化时适配器为恒等映射，保证训练稳定。
- **训练与部署一致性**：训练和部署共用同一冻结的记忆构建机制和因果可见边界，差异仅在于记忆内容分别来自专家轨迹前缀和在线真实交互。

### 2.2 后退时域扩散规划（Receding-Horizon Diffusion Planning）

- **动作块公式化**：每个决策步骤联合预测一个长度为 K 的离散动作块 ât = [â⁰t, ..., âᵏ⁻¹t]，其中 â⁰t 是当前控制决策，其余为近未来动作（辅助规划目标，不承诺连续执行）。
- **有效前缀监督与损失加权**：训练时仅对轨迹中实际存在的动作前缀（长度 Lt = min(K, T−t)）计算损失，超出部分用 Stop 填充并屏蔽，避免合成尾部产生误导梯度。损失函数为：
  Lact = Σ vt,h · ct,h · γh · CE(zt,h, χ(ā*t,h)) / Σ vt,h · ct,h · γh
  其中 v 是有效前缀掩码，γ = 0.7 为时域衰减权重（强调近期动作），ct,h 是基于动作上下文重加权（CAR）的上下文系数，βcar = 0.1。
- **离散扩散生成**：推理时从全 [MASK] 状态出发，经 S=12 次迭代去噪逐步解析动作 token；单调原点采样器以线性增长的转移概率将掩码替换为动作 token，且只在专用动作 token 集 χ(A) 上采样，保证输出可执行。
- **关闭循环执行（plan-K, execute-one）**：完整生成动作块后仅执行第一个动作，收到新观测后重新规划整个动作块；未来位置的动作预测仅作为当前决策的结构化规划变量，不作为开环命令序列。

### 2.3 LiteStop：解耦的显式终止模块

- **初始全掩码表征**：复用扩散策略在初始全掩码前向中产生的 K×|A| 动作 logits 网格 H(0)t，此时所有动作槽均为掩码状态，反映策略在纯规划状态下的响应。
- **轻量停止预测器**：通过 LayerNorm + MLP（W1、W2）将 H(0)t 映射为标量停止 logit，再经 sigmoid 得到停止概率 p_stop。
- **冻结策略监督**：以专家动作是否为 Stop 构造二值标签（λ+ = 4.0 正类加权）；训练时整个导航策略冻结，仅优化 LiteStop，不反向传播到视觉、记忆或规划组件。
- **决策规则**：最终终止判定为 LiteStop 触发（p ≥ ηstop）或动作块首动作本身为 Stop 二者的逻辑或。ηstop = 0.50（在 64 轨迹校准集上选择）。

### 3.1 数据集与基准

## 6. 主要结论与发现

- DreamFly 在 OpenFly 的 test-seen/test-unseen 上分别达到 **32.04%/29.46% SR**、**28.22%/23.54% SPL**，均为所有对比方法中的最好成绩，同时实现最低导航误差（44.87 m/45.29 m）。
- 三个组件的消融均导致性能下降，表明历史上下文、未来动作结构和显式终止三项能力**互补且缺一不可**。
- 距离分组分析显示：LiteStop 在短距离（目标附近）贡献最大；历史记忆在中距离贡献突出；长距离下记忆与动作块规划互补。
- 随机序列的 SR 明显受初始距离影响：在初始距离已小于 20 m 的轨迹上成功率更高，说明其非零成功率并非源于目标导向行为。
- 定性案例中：移除记忆导致目标参照丢失（最终误差 43.5 m vs 10.9 m）；移除动作块导致过早偏离路径（58.1 m vs 2.2 m）；移除 LiteStop 导致进入目标区域后继续漂移（23.0 m vs 12.5 m）。

## 7. 优点（方法或实验设计上的亮点）

- **因果时间界定的严谨性**：明确区分"历史建模"与"何时可读取"两个问题，通过读-先于-写协议在训练与部署间保持一致的信息可见性，避免了传统记忆方法中信息泄漏的模糊性。
- **后退时域与闭环控制的结合**：plan-K, execute-one 策略既获得了短期前瞻的动作结构，又保留了基于新观测的闭环重规划，避免开环执行导致的误差累积。
- **终止判断的专门化设计**：LiteStop 将终止从动作生成中解耦，从初始全掩码规划状态估计停止概率，专门校准冻结策略的终止倾向；不修改原始运动策略，具有即插即用的灵活性。
- **记忆压缩机制**：结合 CLIPSeg/OWLv2 双路由器的候选构建、活动轨迹证据累积、单观测提升和固定容量槽设计，在有限输入预算下保留跨观测的稳定证据和瞬时关键信息。
- **消融与解释性分析**：既有标准消融，又有距离分组、初始条件分层、阈值校准分析，从多个维度揭示组件的作用机制，增强了结论的可信度。

## 8. 不足与局限

- **实验场景局限**：仅在模拟环境中验证（AirSim/UE），未在物理 UAV 平台上部署；真实世界的感知噪声、风扰、动力学偏差和 sim-to-real 域迁移问题尚未验证。
- **基准单一性**：只用 OpenFly 一个基准，缺少在 AerialVLN、CityNav、OpenUAV 等其他空中 VLN 数据集上的验证，跨数据集的泛化结论有限。
- **OSR 表现偏弱**：DreamFly 的 OSR（46.77%）低于若干基线（如 CMA 的 69.32%、AerialVLN 的 65.66%、OpenFly-Agent 的 52.73%），表明其"到达过目标附近"的能力反而不如某些方法；高 SR 但低 OSR 的组合意味着 DreamFly 更依赖精确终止，而在覆盖/探索目标区域方面的能力可能不足，存在潜在的偏差风险。
- **LiteStop 校准规模偏小**：阈值选择基于 64 条轨迹的校验集，统计稳定性有限；且 ηstop = 0.50 相比 ηstop = 0.80 产生了大量（45/64）LiteStop 自身触发，可能过度干预。
- **训练数据不平衡**：训练集动作分布明显偏向前进动作，可能引入先验偏差；虽做了部分数据标准化，但未讨论类别不平衡对策略的影响。
- **计算资源披露不足**：未说明具体 GPU 资源和训练时长，影响复现的可行性和成本评估。
- **横穿偏置（covariate shift）未处理**：论文明确说明因果记忆定义不缓解模仿学习中的协变量偏移问题，长期闭环执行下的状态分布漂移仍可能累积误差。
- **对冻结模型依赖度高**：候选构建依赖 CLIPSeg/OWLv2 等冻结模型，且记忆机制较复杂，实际部署时的推理开销和模块依赖需进一步评估。
