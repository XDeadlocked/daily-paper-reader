## 摘要
通过强化学习(RL)训练的GUI代理在移动平台上展示了强大的环境学习能力。然而，RL通常需要大量的真实环境交互，导致高资源成本和不稳定性，尤其是在GUI场景中。为了解决这些问题，我们提出了WM-R1，这是第一个利用世界模型而非真实环境来训练移动GUI代理的强化学习框架。具体来说，世界模型在所有rollout中作为状态转换的来源，取代了训练循环中的真实Android环境。WM-R1还将世界模型直接嵌入思考过程，使代理能够在执行最终动作之前推理候选动作的后果。关键的是，WM-R1消除了对真实环境交互的需求，支持基于世界模型的大规模并行和步骤级粒度轨迹生成，并引入了多维基于规则的奖励，共同优化任务成功率、轨迹效率和世界模型利用率。为了高效训练，我们策划了一个包含2000个具有挑战性任务的高质量数据集。在Android移动基准上的实验表明，WM-R1训练的代理显著优于仅使用GRPO的基线和推理时模拟方法。代码可在 https://github.com/genalyu/WM-R1 获取。

## Abstract
GUI agents trained with reinforcement learning (RL) have showcased strong environment learning capabilities on mobile platforms. However, RL typically demands extensive real-environment interactions, leading to high resource costs and instability, especially in GUI scenarios. To address these, we propose WM-R1, the first reinforcement learning framework that trains mobile GUI agents with world models instead of real environments. Specifically, world models serve as the source of state transitions during all rollouts, replacing the real Android environment within the training loop. WM-R1 also embeds world models directly into the thinking process, enabling agents to reason about the consequences of candidate actions before committing to the final action. Crucially, WM-R1 eliminates the need for real-environment interaction, supports massively parallelized and step-level granularized trajectory generation grounded in world models, and introduces a multi-dimensional rule-based reward that jointly optimizes task success, trajectory efficiency, and world model utilization. For efficient training, we curate a high-quality dataset of 2000 challenging tasks. Experiments on Android mobile benchmarks demonstrate that WM-R1-trained agents significantly outperform GRPO-only baselines and inference-time simulation methods. Code is available at https://github.com/genalyu/WM-R1 .

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：移动端 GUI 代理（GUI Agents）通过视觉感知与动作执行来自动化复杂数字任务，强化学习（RL）是训练这类代理的有效途径。然而，现有 RL 方法（如 GRPO）在训练时需要大量与真实 Android 环境交互，带来三大瓶颈：
  - **计算成本高**：环境交互比模型推理慢几个数量级；
  - **不可逆性**：一个错误动作即可导致长程轨迹失败；
  - **环境噪声**：非确定性状态转换会污染奖励信号。
- **现有世界模型研究的不足**：文本、像素、代码三种范式（分别预测语言/DOM、合成截图、生成可渲染 HTML）虽然取得进展，但**都仅在推理时作为即插即用的模拟器**使用，未改变 RL 训练循环本身——"如何把世界模型当作训练环境本身"仍是根本挑战。
- **论文的定位**：首次提出 WM-R1——**首个完全在世界模型模拟环境中训练移动 GUI 代理的强化学习框架**，用世界模型取代真实环境，实现零真实环境交互、大规模并行、步骤级粒度化的轨迹生成。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想
- 用**世界模型 W**（Code2World-8B，训练时冻结）替代真实环境，负责所有 rollout 中的状态转换：
  - **推理中嵌入世界模型**：代理在思维链（CoT）中通过 `<call_wm>` 机制模拟候选动作，观察预测的下一帧截图后修正决策，再输出最终动作；
  - **完全模拟的轨迹生成**：整条轨迹的状态转换均由 `φ̂_{t+1} ~ W(· | φ̂_t, a_t)` 产生。

### 2.2 关键技术细节
- **世界模型集成方式**：不同于将世界模型当作独立对话轮次，WM-R1 将 `<call_wm>` 嵌入代理的 thinking 流内部——模拟结果以 System (WM) observation 形式注入同一思考块，实现"思考→模拟→再思考→决策"的多轮推理模式。
- **轨迹生成流程**（每个 task 的每个 rollout）：观察 → 思考（含可选 `<call_wm>`）→ 模拟并继续 → 若不再调用则输出最终动作 → 重复至终止动作或达到 T_max=15。
- **复合奖励设计**：
  - **成功奖励 R_success**：LLM-as-a-judge 将代理最终轨迹与参考解对比，输出二元成功/失败（用 GPT-4o，温度 0，两次评估取平均）；
  - **长度奖励 R_L**：基于 DAST 方法，以参考轨迹长度与最大长度的混合作为长度预算，惩罚冗余步骤；
  - **WM 调用次数奖励 R_WM**：按组内均值归一化，惩罚过度使用/不足使用世界模型；
  - 加权组合：`R = α·R_success + β·R_L + γ·R_WM`（α=1.0，β=0.5，γ=0.1）。
- **训练算法**：沿用 GRPO（组相对优势，公式如第 1 节的式 (1)–(2)），但优势由复合奖励计算，完整伪代码见附录 Algorithm 1。

### 2.3 数据与模型配置
- 基础模型：Qwen2.5-VL-3B / 7B；泛化实验另用 Qwen3-VL-4B / 8B；
- 世界模型：Code2World-8B（冻结），从当前截图+动作生成可渲染 HTML，再由无头浏览器渲染为 1080×2400 截图；
- 训练数据：由 AndroidCode、GUI-Odyssey、GUI-R1 三个公开数据集混合，**过滤掉零样本成功率>80%（过易）和<5%（过难）的任务**，最终随机采样 2000 个中等复杂度任务。

## 6. 主要结论与发现

1. **全面超越基线**：WM-R1-7B 在 AndroidWorld 达 39.8%（超 UI-R1-7B +9.0、超 UI-TARS 1.5-7B +5.6）；GUI-Odyssey 达 31.6%（超 UI-R1-7B +10.1）；3B 规模同样显著领先。同时大幅优于推理时模拟基线（Qwen2.5 + CW 在 AndroidWorld 上被拉开 8.9–11.1 个点）。
2. **Hard 子集提升更大**：在需要多步推理的困难任务上，世界模型模拟转换提供的增益更突出。
3. **OOD 泛化能力强**：WM-R1 相对零样本平均 OOD 提升约为 UI-R1 的 1.84 倍，表明学到的是"使用世界模型推理的策略"而非"记忆特定 UI 模式"。
4. **消融关键组件**：CoT 推理最关键（去掉后 −5.2/−4.9）；长度奖励和 WM 调用奖励贡献互补。
5. **世界模型使用呈现三阶段掌握曲线**：探索（~4 次/轨迹）→ 校准（~2.5 次/轨迹）→ 选择性利用（~1.8 次/轨迹），代理学会在不确定的关键决策点才调用模拟。
6. **架构无关性**：Qwen3-VL 上同样表现出一致的显著提升（8B：AW 44.5，超 UI-R1-8B +9.3）。

## 7. 优点与亮点

- **范式创新**：第一次把世界模型从"推理时插件"升级为"训练环境本体"，从根本上绕开真实环境交互的三大瓶颈（成本、不可逆、噪声），是环境无关 RL 训练的有力验证。
- **"思考-模拟-再行动"的可解释推理**：`<call_wm>` 内嵌思维链使代理的决策过程透明可审计，世界模型充当"心理演练场"（scratchpad）——既可在犯错前自纠（如案例研究中调整点击坐标），又天然产生可解释的推理轨迹。
- **奖励设计兼顾多维目标**：成功、效率、模拟预算三者在组内相对比较下联合优化，激励机制清晰可控。
- **训练稳定且高效**：无环境噪声带来更低方差、更高策略熵、更持续的探索，且单张 H200 即可完成训练；相较于在线 RL（MobileGUI-RL 36.5h）大幅节省算力和基础设施。
- **工程与评测严谨性**：公布完整超参数、算法伪代码、推理开销分解，做 LLM 评估器人工校准（93.5% 一致性），并在多种基线上横向对比。

## 8. 不足与局限

- **强依赖世界模型保真度**：训练信号完全来自 Code2World 的模拟状态。对于动画、实时数据更新、第三方动态 widget 等，码生成式世界模型可能失真，错误的模拟会误导策略。
- **动作空间受限**：仅支持离散动作（点击坐标、输入文本、滚动等），难以扩展到自由光标移动、拖拽等连续控制场景。
- **实验覆盖不足**：消融只在单一基准（AndroidWorld 7B）上做；未验证 3B 规模下的消融结论；未给出多次运行的统计显著性和标准差（表 1）。
- **数据过滤可能带来分布偏差**：剔除过易/过难任务后，训练集集中于中等难度，与真实世界任务难度分布可能不一致，影响部署时的鲁棒性。
- **评估依赖 LLM judge**：虽然经人工校准，但 judge 由 GPT-4o 承担，存在主观性和不可复现（温度 0 缓解但未消除）的风险；对"语义等价"的判断也并非完全确定性的。
- **声称"零真实环境交互"需注意边界**：训练确实不需真实环境，但世界模型（Code2World）本身的训练数据仍来源于真实 GUI 轨迹；世界模型若有系统性偏差，会传导给代理。
- **平台泛化未验证**：实验全部基于 Android，未覆盖 iOS/Web 等平台。
