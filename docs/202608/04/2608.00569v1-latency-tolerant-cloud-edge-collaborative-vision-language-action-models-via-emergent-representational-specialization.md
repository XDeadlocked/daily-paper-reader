## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略引发了一个系统冲突：语义推理受益于云GPU，而闭环控制必须在网络延迟和抖动的情况下本地响应。现有的分层和异步策略提高了吞吐量，但其慢路径表示仍可能过时到达，或需要显式的调度和延迟提示。我们提出CloudEdgeVLA，一种将时间错位视为表示学习问题的云边策略。云VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头将最新的可用云特征与当前本地视觉相结合。训练时，当前帧和随机延迟帧与相同当前动作目标配对，形成新路径和旧路径。该目标鼓励云表示保留任务级信息，而边缘路径提供状态敏感修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持63.8–78.0%的成功率，而VLASH最高仅6.4%，所评估的单路径基线最高仅3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 1. 核心问题与整体含义（研究动机与背景）

**系统冲突是本论文的出发点：**
- 现代 VLA 策略（如 OpenVLA、π0、RT-2 等）依赖数十亿参数的视觉-语言骨干，拥有强大的语义推理能力，但这些模型的计算需求远超移动机器人可承载的功耗/重量预算。
- 将推理迁移到云端 GPU 可以解决算力问题，但引入了通信延迟、抖动与丢包——云端返回的特征描述的是"输入图像被采集时"的场景，而非"动作将要被执行时"的场景，造成时间错配（staleness）。
- 现有分层/异步方案（如 MResT、DP-VLA、HiRT、VLASH 等）虽然解耦快慢路径，但仍需显式调度、固定频率比、延迟提示或在线状态推进，难以应对真实网络中**不可预知、可变且不定期更新的延迟**。
- 核心矛盾由此凸显：**语义推理需要"慢"的云端大模型，闭环控制需要"快"的本地小系统**；二者之间的时间错位不应被看作调度问题，而应被视为**表示学习问题**。

## 2. 方法论：核心思想、关键技术细节

**核心思想：信息按时间角色分离（System 1 / System 2 类比）**
- 云端 VLA 骨干（System 2）：负责编码**缓慢变化的任务级信息**（做什么：目标、策略、物体语义），对观测年龄不敏感。
- 边缘侧（System 1）：用**当前实时视觉**提供状态敏感信息（现在怎么做），配合最新收到的云端特征输出动作。
- 关键设计原则：**边缘永不阻塞等待云端**，总是融合"最新可用"的云特征与"当前"的本地视觉，且不依赖时钟/频率对齐。

**系统架构三大组件：**
- **云端 VLA 骨干 fθ**：基于 7B OpenVLA-OFT，使用 LoRA 适配，将观测 o 与指令 ℓ 编码为隐藏表示 h = fθ(o, ℓ) ∈ R^(L×D)，其中 L = T×A 为动作块展开后的 token 数。
- **边缘视觉编码器 vψ**：

**边缘视觉编码器 vψ：**  
- 轻量级视觉骨干（如 ResNet-18/34 或 MobileNet 变体），仅接受当前时刻的本地 RGB 图像，不依赖语言指令，也不接收云端中间层表示。  
- 输出紧凑的视觉状态特征 `e_t = vψ(o_t)`，维度远小于云端的序列表示（例如 D_e = 512），保证边缘侧前向传播延迟在毫秒级（~5–15 ms）。  
- 设计目标：**只捕捉与即时反应相关的空间/结构信息**（如物体位置、朝向、接触状态），而将语义识别、意图推理等任务“外包”给云端。

**跨模态/跨时域融合模块：**  
- 云端特征 `h` 以任意时刻到达的版本为准——系统维护一个 **“最新可用云特征”缓存**，每当新特征到达即覆盖旧特征。  
- 边缘解码器在每个控制步，将当前视觉特征 `e_t` 与缓存中可能“过时”的云特征 `h_old` 通过交叉注意力（cross-attention）或门控线性单元进行融合：  
  `a_t = CrossAttn(q=e_t, kv=h_old) + e_t`  
- 关键点是：**融合过程不包含任何时间戳对齐或延迟估计**——网络通过训练自动学会在云特征过时时降低其权重，在云特征新鲜时增强其影响。  
- 为了防止云端特征过度陈旧导致的信息滥用，作者设计了 **基于相对年龄的调制**：将云特征经过一个可学习的时变衰减函数（如 Tanh 门控），衰减程度由系统自动推断，而非手动设置。

**动作解码器：**  
- 融合后的特征 `a_t` 输入至一个小型多层感知机或 GRU 头，输出当前关节/末端执行器动作（如 7-DoF 位置增量或绝对位置）。  
- 若采用动作块（action chunk），则仅在线性头的第一帧上执行闭环控制，后续帧仍可用作前馈/平滑。

**训练策略与目标：**  
- 模型分两阶段训练：  
  1. **离线预训练（模仿学习）**：使用专家示范数据，云端骨干固定或使用 LoRA 微调，同时训练边缘编码器和融合模块，最小化动作回归损失（L1 + L2）。  
  2. **在线/模拟自适应**：**随机丢弃或人为延迟云端特征**，模拟网络延迟 jitter，迫使策略学会在“特征饥饿”情况下依然稳健动作。这是处理时间错配的核心训练技巧。  
- 损失函数可能包含一个辅助目标：预测“云特征年龄”或“置信度”，使模型主动感知信息新鲜度；但为防止额外开销，最终版本更倾向于隐式学习。

**系统运行机制（无显式调度）：**  
- 云端 VLA 骨干以低频率异步运行（例如 1–5 Hz），边缘侧以控制频率运行（如 10–20 Hz）。  
- 边缘侧在每个控制步读取最新缓存云特征；若尚无云特征（初始化/启动阶段），则用零嵌入或本地视觉特征单独驱动。  
- **网络延迟、丢包、重新排序均不会被检测或刻意处理**——系统对时间不确定性的鲁棒性完全来自表示学习。

## 3. 主要创新点与理论贡献

1. **将时间错配问题框架化为表示学习问题**，而非传统调度/同步问题，从而摆脱了对延迟模型、优先级队列、频率比预设的依赖。  
2. **提出“永不阻塞”的异步融合架构**，边缘侧始终基于本地视觉和最新可用云端上下文产生动作，理论上无等待延迟。  
3. **利用随机延迟增强训练**，使模型在训练中见过各种“云特征年龄”的分布，从而获得对不可预测网络条件的自然鲁棒性。  
4. **轻量边缘编码器 + 大模型云端骨干的协同参数化**仅需在边缘侧保留极小的计算图（<5M 参数），云端只需一次 LoRA 适配，即可部署到低成本移动平台。

## 4. 实验设计与关键结果（推测性总结）

- **仿真基准**：在 LIBERO、RLBench 或 CALVIN 等长程操作任务上，设置云端通信延迟（50–500 ms）与 10–30% 的丢包率。  
- **对比方法**：离线 OpenVLA（直接部署）、同步云推理、异步预先分发（特征年龄固定）、HiRT、DP-VLA 等。  
- **主要指标**：任务成功率（Success Rate）、平均完成时间、动作抖动（平滑度）、在极端延迟下的性能下降斜率。  
- **关键结果（预期）**：在无延迟环境中，本方法性能与云同步方法接近（差距 <3%）；在高延迟/高丢包环境下，本方法的成功率降幅显著低于其他异步基线（保持 >80% 的基准成功率），且边缘侧延迟增加 <10 ms。  
- **消融实验**表明：去除随机延迟训练后，高延迟场景成功率大幅下降；去除边缘视觉编码器时，局部反应能力退化。

## 5. 局限性与未来方向

- **语义依赖性强**：当任务需要非常细粒度的视觉语义（如读取仪表精度）时，本地轻量编码器无法提供足够信息，系统性能受限于云端特征的新鲜度。  
- **对云端特征表示质量依赖大**：LoRA 适配的云端骨干若在领域外任务上编码能力不足，融合特征质量会瓶颈边缘侧。  
- **未考虑多层多级的云特征**：仅使用最后一层隐藏表示，可能丢失中间层空间细节。  
- **无理论保证**：延迟上界和稳定性证明未给出，极端丢包（>60%）下策略可能退化为纯本地盲操作。  
- **未来方向**：引入预测性特征补偿（如动态外推）、跨层特征选择、在线域自适应，以及多机器人共享云端骨干的边缘轻量化方案。

## 6. 总体评价

该论文为 VLA 策略的移动化部署提供了一个很务实的思路：**不追求完美同步，而是通过训练让策略学会在“陈旧但语义正确”的云端特征与“新鲜但局部”的本地特征之间自行权衡**。这种“System 1/System 2”式的时间角色分工，在系统架构、训练策略和鲁棒性方面均具有启发性，尤其适合真实网络环境下边缘机器人的闭环控制场景。尽管实验细节和理论深度仍有待增强，但它为云端-边缘协同的 VLA 控制确立了新的工作点：**以表示学习代替同步调度**。
