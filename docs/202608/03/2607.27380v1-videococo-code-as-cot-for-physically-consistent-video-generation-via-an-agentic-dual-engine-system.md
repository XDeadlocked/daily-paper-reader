## 摘要
文本到视频模型已取得显著的视觉质量，但由于场景的时间演化必须从高度压缩的文本提示中隐式推断，它们仍难以生成物理上一致的动态。现有的思维链方法引入了中间计划或视觉状态，但这些表示通常不可执行或时间稀疏，限制了它们实例化和控制完整时空过程的能力。为解决这一局限，我们提出了VideoCoCo，一个智能体双引擎框架，其中可执行的Blender代码充当过程级思维链。给定文本提示，编码智能体合成一个Blender程序，明确指定场景及其时间演化。可执行的模拟引擎运行该程序以产生确定性的时空草稿，随后通过生成式视频引擎以草稿条件编辑的方式将其转换为逼真的视频。这种分解将过程级推理与高保真视觉实现分离。为使视频编辑器适应模拟草稿，我们构建了VideoCoCo-3K，一个精选的草稿-指令-目标三元组数据集。VideoCoCo将OmniWeaving基线在PhyGenBench上从0.475提升至0.558，在VBench-2.0上从52.18提升至77.88，在两个基准上均取得最佳平均分数。这些结果表明，可执行代码为物理一致的视频生成提供了一种有效、可控且可检查的中间表示。

## Abstract
Text-to-video models have achieved remarkable visual quality, yet they still struggle to generate physically consistent dynamics because the temporal evolution of a scene must be inferred implicitly from a highly compressed text prompt. Existing chain-of-thought approaches introduce intermediate plans or visual states, but these representations are typically non-executable or temporally sparse, limiting their ability to instantiate and control the complete spatiotemporal process. To address this limitation, we introduce VideoCoCo, an agentic dual-engine framework in which executable Blender code serves as a process-level chain of thought. Given a text prompt, a coding agent synthesizes a Blender program that explicitly specifies the scene and its temporal evolution. The executable simulation engine runs the program to produce a deterministic spatiotemporal draft, which is subsequently transformed into a photorealistic video by a generative video engine through draft-conditioned editing. This decomposition separates process-level reasoning from high-fidelity visual realization. To adapt the video editor to simulated drafts, we construct VideoCoCo-3K, a curated dataset of draft-instruction-target triplets. VideoCoCo improves the OmniWeaving baseline from 0.475 to 0.558 on PhyGenBench and from 52.18 to 77.88 on VBench-2.0, achieving the best average score on both benchmarks. These results demonstrate that executable code provides an effective, controllable, and inspectable intermediate representation for physically consistent video generation.

## 2. 方法论

### 2.1 总体架构：智能体双引擎系统
VideoCoCo 将物理一致视频生成分解为两个互补引擎：**可执行仿真引擎**负责过程级推理，**生成式视频引擎**负责高保真视觉化。二者的分工刻意设计为：一个引擎"决定发生了什么"，另一个引擎"决定它看起来如何"。

### 2.2 阶段一：可执行仿真引擎（Executable Simulation Engine）

- **Code-as-CoT 程序合成**：给定输入提示 \( p \)，编码智能体 \( A_{code} \) 合成一个自包含的 Blender Python 程序 \( c = A_{code}(p) \)，该程序显式指定场景、物体的物理属性以及目标事件的时间演化。
- **选择 Blender Python 的三大原因**：① **显式性**——每个对象、运动与相互作用都必须被声明，消除了文本计划中的欠指定问题；② **可执行性**——程序能够实际运行，而非仅被描述；③ **可检查性**——代码可读、可修改、可重执行，推理过程透明。
- **沙箱执行与草稿渲染**：程序在隔离的 Blender 环境 \( B \) 中运行，产生确定性时空草稿 \( d = B(c) \)。沙箱保证同一程序必然产生同一草稿，渲染错误作为诊断信号返回用于代码修订。草稿是**有意的低保真**（白色黏土风格，无写实材质与复杂光照），但**时间上密集**——每一帧对应所编程过程的一个物理实例化状态。因此 \( d \) 不是候选输出，而是固定"何时发生什么"的结构支架。

### 2.3 阶段二：生成式视频引擎（Generative Video Engine）

- **编辑指令构造**：原始提示 \( p \)（压缩、抽象、偏向"事件是什么"）与草稿 \( d \)（密集、风格化、偏向"事件如何展开"）粒度差异大，直接传入编辑器会导致外观欠指定或运动与草稿冲突。因此引入指令智能体 \( A_{edit} \) 综合两者，生成**外观聚焦**编辑指令：\( e = A_{edit}(p, d) \)。指令 \( e \) 负责描述主体、材质、光照和电影风格，并被明确禁止重新定义草稿中已有的运动。
- **草稿条件视频编辑**：草稿 \( d \) 与指令 \( e \) 联合输入草稿条件视频编辑器 \( G_\theta \)，生成最终视频 \( \hat{v} = G_\theta(d, e) \)。\( d \) 锚定时空结构，\( e \) 指定写实外观。编辑器被要求"重风格化已实例化的过程"而非"凭空想象过程"，这比直接 T2V 生成容易得多。

### 2.4 VideoCoCo-3K 数据集构建

- **动机**：公开视频编辑数据集仅含自然视频对，缺乏"模拟白黏土草稿—共享同一时空过程的写实视频"配对监督。
- **教师式三元组构造**：对每个提示 \( p_i \)，仿真引擎产生草稿 \( d_i \)，指令智能体构造指令 \( e_i \)，然后使用高保真教师编辑器 \( G_T \)（Seedance 2.0）生成逼真目标 \( y_i = G_T(d_i, e_i) \)。Seedance 2.0 被选中是因为它既能真实还原草稿运动又能产生照片级帧——训练目标所需的两大性质。
- **数据集规模**：\( \mathcal{D}_{VideoCoCo-3K} = \{(d_i, e_i, y_i)\}_{i=1}^{3000} \)。**排除了评估基准中的所有提示及其近重复项**，避免数据泄漏。保留原始提示和 Blender 程序作为元数据，便于检查和扩展。

### 2.5 编辑器适配与端到端推理

- **训练目标**：在 VideoCoCo-3K 三元组上以标准条件去噪目标训练：\( L(\theta) = \mathbb{E}_{(d,e,y),t,\epsilon}[\|\epsilon - \epsilon_\theta(z_t, t, d, e)\|_2^2] \)，其中 \( z_0 \) 为目标潜在表示，\( z_t \) 为其在扩散时间步 \( t \) 的加噪版本。初始化自 OmniWeaving 基座生成器，比较全量微调与 LoRA 两种策略。
- **端到端推理**：用户仅输入提示 \( p \)，编码智能体生成程序 \( c \)，沙箱渲染草稿 \( d \)，指令智能体构造指令 \( e \)，适配后的编辑器输出最终视频 \( \hat{v} \)。无需人工标注或辅助输入，整个流程全自动、可检查、可复现。

## 6. 主要结论与发现

1. **可执行代码是有效的物理一致性中间表示**：在 PhyGenBench 上，VideoCoCo 将 OmniWeaving 基线的平均一致性从 0.475 提升至 0.558（+0.083），为所有对比方法中最佳，超过最强开源基线 Wan2.2-TI2V-5B（0.544）；在 VBench-2.0 上从 52.18% 提升至 77.88%（+25.70 个百分点），同样为最佳平均分。
2. **草稿贡献物理，编辑贡献外观，两者互补**：Tune-Free 变体（不更新任何参数）已从 0.475 提升至 0.506，证明草稿本身携带物理信息；LoRA 适配在此基础上进一步涨至 0.558，证明编辑适配带来额外增益。
3. **物理先验最弱的类别提升最大**：材料动力学（+0.133）和热学（+0.078）在 PhyGenBench 上增益最高；VBench-2.0 上力学（+29.52）与热学（+20.84）提升最大。这验证了代码草稿补充的是物理动力学而非表面真实感——越依赖数据先验的类别越受益于显式仿真。
4. **LoRA 优于全量微调**（0.558 vs 0.535）：编辑器仅需学习"白黏土草稿→写实视频"的窄域映射，低秩适配保留基座模型的视觉先验，而全量微调在有限三元组数据上更容易过拟合。
5. **双引擎分解可行**：仿真引擎解决"什么发生"（确定性、可检查），生成引擎解决"如何呈现"（照片级、高保真），两个此前难以同时满足的目标通过分工得以协调。

- **额外推理延迟**：端到端推理需依次经历代码生成、沙箱渲染、指令构造、视频编辑四步，相较直接 T2V 生成引入了显著延迟，作者在结论中坦承这一点但未提供量化数据。
- **模拟器表达力上限**：方法受限于 Blender 模拟器的可表达范围，对湍流流体等高度复杂物理现象难以零样本合成。物理复杂度超过 Blender 能力时，草稿本身可能不准确，误差会传播到最终视频。
- **数据集规模与覆盖有限**：3000 个三元组覆盖的物理场景、物体类别、风格范围相对有限，可能影响编辑器对分布外提示的泛化能力。场景多样性不足会造成对常见物理过程过拟合、对罕见过程失效。
- **单编辑器、单教师验证**：仅验证了 OmniWeaving + Seedance 2.0 的组合，结论对视频编辑器的可迁移性未经验证。教师模型的偏差可能被蒸馏进适配后的编辑器中。
- **评判与评估偏差风险**：PhyGenBench 依赖 GPT-4o 评判，VBench-2.0 采用预注册子集，两者都可能引入评估偏差。缺少人工评估（如人类标注者对物理一致性和视觉质量的独立评分）来交叉验证。

## 9. 与现有方法的深层对比与定位

- **相对于物理引导生成（Physics-Guided Generation）**：已有方法多通过物理损失约束、刚体动力学模型或轻量物理模拟器直接注入生成过程，但往往局限于特定物体类别（如刚体、流体）或特定交互类型。VideoCoCo 以通用 Blender 物理引擎为桥，不针对某一物理定律定制损失函数，而是通过程序化描述覆盖多类物理现象，范围更广。
- **相对于视频编辑方法**：VideoCoCo 本质上做的是"草稿→视频"的条件编辑，但区别于传统时序编辑任务（如换风格、换主体），其编辑条件（白黏土草稿）是密集的、空间完整的、时间对齐的视觉输入，由此将任务从"语义引导的修改"转变为"外观赋予"，大幅降低了生成器对物理推理的负担。
- **相对于关键帧/布局引导方法**：布局和关键帧是稀疏中间态，两个布局之间模型仍需自行补全连续过程；VideoCoCo 的草稿逐帧锚定，中间过程无自由发挥空间，物理一致性从"插值问题"变为"重着色问题"。
- **方法论启示**：该方法提出了一个"外部化推理+内部化生成"的通用范式，即用确定性的外部工具（仿真器）承担生成模型最不擅长的逻辑链条，用生成模型承担外部工具最不擅长的感知丰富性。该范式对其他需要"逻辑正确+外观逼真"的任务（如空间推理、反应视频、工具使用动画）具有迁移潜力。

## 10. 关键细节的再审视与潜在风险

- **指令智能体的信息瓶颈**：系统将草稿与原始提示的融合完全寄托于 LLM 生成的文本指令 \( e \) 上。若 \( e \) 遗漏草稿中某个动力学细节的视觉对应关系，生成器将无法恢复该细节。文本作为中间接口具有信息损失风险，作者未对 \( e \) 的内容质量开展系统性评估。
- **草稿信任度问题**：如果 Blender 程序本身编写错误（如物体未正确碰撞、力场参数不精确），草稿会"看似合理但不物理"。由于草稿是白黏土风格，低纹理使其物理误差不易被肉眼察觉，可能误导编辑阶段生成"外观真实但物理依旧错误"的视频，反而比直接生成的错误更隐蔽。
- **教师模型的主导角色**：训练目标 \( y_i \) 完全由 Seedance 2.0 产生，最终模型学到的"草稿→视频"映射的上限即 Seedance 2.0 对草稿运动的理解水平。若 Seedance 2.0 在某种物理过程中无法忠实践行草稿，适配后的编辑器也将继承该缺陷。
- **代码生成失败的模式**：文中未报告编码智能体在从未见过的物理场景下的代码合成成功率。若代码合成失败率较高，端到端流程的实际可用性将显著下降，因为 Blender Python API 的语法、物理参数调试是出了名的需要反复试错的任务。
- **版权与合规隐患**：训练数据中使用商业模型（Seedance 2.0）生成的目标视频进行再训练，其条款合规性、生成内容的版权归属、以及"蒸馏商业模型行为"是否违反服务协议，文中均未讨论。

## 11. 展望与开放问题

1. **验证集规模扩展**：将 VideoCoCo 由 3000 个三元组扩展至数万规模，覆盖更多物理现象（流体湍流、柔体形变、相变传热、声学现象等），并测试数据规模与性能的缩放规律。
2. **多基座适配**：在不同架构的视频生成器（如 DiT、UNet、自回归模型）上验证该中间表示的有效性，检验其是否为生成器无关的通用中间层。
3. **多模态中间表示融合**：探讨是否需要将代码、草稿、物理场（如应力场、速度场）等多通道信息联合作为条件，以超越纯视觉草稿可承载的信息量。
4. **动态规划的代码生成**：引入"代码规划器"预先进行高层次物理分解，再逐步细化生成 Blender 程序，提升复杂场景的代码成功率。
5. **自适应保真度渲染**：根据物理现象的类型动态决定草稿的渲染保真度——简单刚体可用超低保真帧，流体或柔体可能需要中间保真度以保留细节特征。
6. **自动评估框架**：消除对 MLLM 评判员的依赖，开发基于物理引擎回放比对的量化评估协议，以更低成本、更可复现的方式衡量视频物理一致性。

## 12. 价值判断总结

VideoCoCo 的贡献具有**方法论上的范式意义**而非仅仅指标提升：它将"程序合成—物理仿真—条件视频编辑"的组合确立为一个可复用的框架，在视频物理一致性问题上给出了"用外部确定性引擎补足模型因果推理短板"的明确路线。其技术路线清晰、工程实现紧凑、实验设计合理，在 PhyGenBench 与 VBench-2.0 上的提升幅度显著且可解释。方法的不足（延迟、表达范围、数据规模）本质上源于"外置推理"范式的固有边界，而非实现缺陷。未来，随着代码生成模型能力的增强和仿真引擎与视频生成器的接口标准化，这一范式的成本将进一步下降，其对视频生成领域（乃至更广泛的可控内容生成领域）的影响值得持续关注。
