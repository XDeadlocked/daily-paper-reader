## ABSTRACT 

Vision-language-action (VLA) policies repeatedly invoke inference to control robots, making graphics processing unit (GPU) energy a recurring cost of task execution. Reducing energy per inference call, however, may not reduce energy per successful task if numerical errors increase failures or slower inference pro-longs execution. We therefore target GPU energy per successful task while pre-serving task success and keeping the inference-latency increase within 10%. Our approach builds on two observations: quantization sensitivity varies across ac-tion classes, model layers, and weights versus activations; and numerical preci-sion changes the workload, shifting favorable GPU operating points. We intro-duce ActTune, an action-aware framework that connects layer-wise precision al-location with workload-dependent GPU operating-point selection over requested frequency–power-cap pairs. A lightweight decision tree learns its splits and leaf precision configurations directly from configuration action errors, then selects pre-cision before each policy call. The controller forecasts the next workload and applies the selected GPU operating point asynchronously using a lookup table calibrated under a latency budget. A shared resident quantized weight bank en-ables configuration switching without weight reconstruction or additional policy evaluations. On LIBERO, a benchmark for lifelong robot learning, ActTune im-proves mean task success by up to 2.3% relative to state of the art. Relative to the original BF16 implementations, it delivers up to 2.02 × faster inference and, with GPU operating-point adaptation, reduces energy per successful task by up to 76.8%. 

## 1 INTRODUCTION 

VLA models translate visual observations and language instructions into robot actions (Kim et al., 2024). For battery-powered robots, repeated onboard inference consumes limited battery energy and can shorten operation between charges. Reducing inference energy is therefore important for extending robot endurance. Dynamic voltage and frequency scaling (DVFS) offers a direct way to pursue this goal by lowering power consumption (Tang et al., 2019). However, lower frequencies prolong inference, which can offset energy savings and delay action updates. The need for timely responses therefore limits how aggressively frequency can be reduced. Numerical precision and GPU operating-point control offer complementary ways to reduce this cost. Quantization lowers weight and activation precision, changing computation and memory traffic, but the resulting numerical errors can also perturb predicted actions. We define a GPU operating point as a requested frequency–power-cap pair. Adjusting these settings trades execution speed against power consumption. Lower frequencies may reduce power, yet longer inference can offset these savings and delay the robot’s response to new observations. Crucially, these two controls are coupled: precision determines the workload on which GPU operating-point control operates. An energy-efficient operating point for one precision configuration may therefore be less effective for another. Existing work provides useful foundations for this connection. VLA quantization methods use ac-tion or task sensitivity to allocate precision (Xu et al., 2026; Akbari et al., 2026; Ranjan & Savakis, 2026), while temporal-dynamic-aware quantization for VLA models (DyQ-VLA) and motion-aware vector quantization (MotionVQ) adapt precision during execution using motion signals (Zheng et al., 2026; Song et al., 2026). However, compression objectives such as model size and bit-operation budgets do not directly capture GPU energy during task execution (Ranjan & Savakis, 2026). Other work studies energy efficiency through quantized robotic policies or device–edge execution place-ment (Park et al., 2025; Zhou et al., 2026), and PiQi, a framework for partially quantized infer-ence, combines partial quantization, processor placement, and DVFS for general deep neural net-work (DNN) inference (Aghapour et al., 2024). Building on these directions, we investigate how action-aware precision allocation and workload-dependent GPU operating-point selection can work together to reduce energy per successful robot task. Our approach is motivated by two observations. First, quantization sensitivity depends on both the action being performed and where numerical error is introduced in the model. For example, coarse approach motion may tolerate small deviations, whereas final alignment may require greater accu-racy (Figure 1). Using a fixed set of action classes learned from training actions, short quantized interventions reveal sensitivity differences across action classes, Transformer blocks, and weight versus activation precision (Figure 2(b–c)). Second, hardware measurements show that different nu-merical precisions can favor different GPU operating points (Figure 3). Together, these observations suggest a two-stage adaptation strategy: use action sensitivity to guide precision allocation, then use the resulting workload to guide GPU operating-point selection. We introduce ActTune , an action-aware framework that implements this strategy. Before each ac-tion chunk is generated, a lightweight decision tree uses current proprioception and the preceding predicted action chunk to select a layer-wise weight and activation precision configuration. Offline calibration learns the tree splits and leaf configurations directly from action error against the BF16 reference policy under precision and storage budgets. A shared resident quantized weight bank sup-ports configuration switching without reconstructing weights or storing a complete model copy for every leaf. This design enables action-aware precision selection with only one policy inference call per action chunk. ActTune profiles frequency and power-cap settings on replayed training workloads with the preci-sion selector fixed. It selects the candidate table with the lowest estimated energy while limiting the mean inference-latency increase to 10% relative to the same precision selector at the fixed reference GPU operating point, subject to action equality and memory checks. After each call, the controller forecasts the next workload and applies the selected GPU operating point asynchronously. Preci-sion selection uses the current observation. Because matching actions on replayed inputs does not guarantee unchanged closed-loop behavior, the final assessment must consider complete episodes. We therefore evaluate closed-loop task success and energy per successful task, and check the 10% budget using the measured inference latency. Our contributions are: • Empirical characterization. We firstly characterize how quantization sensitivity varies across ac-tion classes, Transformer blocks, and weight versus activation precision, and show that favorable GPU operating points depend on numerical precision. • Action-aware precision and GPU operating-point adaptation. We propose ActTune, which con-nects action-conditioned layer-wise precision allocation with workload-dependent GPU operating-point selection. A lightweight decision tree and a shared quantized weight bank enable online adap-tation with one policy call per action chunk. • Quantitative evaluation. In the evaluated LIBERO comparisons, ActTune improves mean task success by up to 2.3% relative to QVLA, an action-centric VLA quantization framework, and action-guided quantization (ActQuant). ## 2 MOTIVATION 

We examine two empirical questions that motivate ActTune: (1) whether quantization sensitivity depends on the action and on where precision is reduced in the model, and (2) whether different precision configurations favor different GPU operating points. The first determines how precision should be allocated, while the second determines whether hardware settings should adapt to the resulting workload. 

Action- and layer-dependent quantization sensitivity. We first group training action blocks into three fixed classes, C0–C2, using principal component analysis (PCA) followed by K-means (Fig-ure 2(a)). These classes describe patterns in the action data rather than prescribed physical task stages. To measure quantization sensitivity, we insert an eight-action quantized intervention into matched BF16 trajectories and then return to BF16 control. We measure final task success rate using equal-weight averages over Goal, Object, Spatial, and Long. The matched BF16 reference achieves a mean task success rate of 95.0%. Figure 2(b) shows that the same precision configuration can have substantially different effects across action classes. At fixed A4, C1 achieves only 42.5– 45.0% task success across the tested weight precisions, whereas C2 maintains 92.5–95.0%. For C1, changing activation precision has a larger effect than changing weight precision, and increas-ing weight precision alone does not resolve the poor A4 outcomes. Sensitivity is also nonuniform across Transformer layers (Figure 2(c)). For C1, applying W4A4 to layer 0 yields 75.0% task suc-cess, compared with 97.5% when applying the same precision to the other tested layers. Increasing layer-0 activation precision from A4 to A8 raises task success to 97.5%. These results show that pre-cision requirements depend jointly on the action class, model location, and quantized component, motivating action-conditioned, layer-wise allocation of weight and activation precision. 

Precision-dependent GPU energy–latency tradeoffs. We next test whether numerical precision changes the preferred GPU operating point. On an NVIDIA RTX A6000, we sweep requested GPU frequency at a fixed 300 W power cap and sweep power cap at a requested frequency of 1800 MHz (Figure 3). Measurements for each precision are normalized to its own 1800 MHz / 300 W refer-ence, isolating the effect of hardware tuning from the energy differences introduced by quantization. At the kernel level, we benchmark resident INT4 ×INT4, INT8 ×INT8, and BF16 ×BF16 GEMM workloads. The measurements include the output epilogue but exclude input quantization, packing, and transfers. INT4 and INT8 reach their lowest measured GPU energy at different frequencies (Figure 3(a)), showing that the energy–latency tradeoff depends on numerical precision. An ex-ploratory policy-level sweep shows the same tendency during VLA execution (Figure 3(b)). In this exploratory sweep, among measured operating points that increase total benchmark time by at most 1%, the lowest-energy points reduce GPU energy by 20.4%, 22.7%, and 21.0% for BF16, W4A8, and W4A4, respectively, relative to their corresponding reference operating points. ## 3 THE ACT TUNE DESIGN 

3.1 OVERVIEW 

ActTune adapts precision and GPU operating points to reduce energy per successful task while pre-serving task success and limiting the inference-latency increase from operating-point adaptation to 10%. Following Section 2, precision selection accounts for action-dependent quantization sensitiv-ity, while GPU frequency and power cap depend on the resulting workload. The controller selects precision before each policy call and prepares GPU operating points asynchronously between calls by forecasting the next workload. At request t, the policy maps observation ot, comprising images, a language instruction, and proprioception st ∈ Rds , to an action chunk At ∈ RH×7. Each action contains six motion coordinates and a gripper command. A GPU operating point ut = ( ft, p t) pairs the requested frequency ft with power cap pt. The selected precision configuration qt and operat-ing point ut remain fixed throughout inference, including iterative action generation. The predicted chunk provides action-history features for the next request. Figure 4 shows the workflow. Offline calibration learns candidate decision trees from configuration errors and selects their complexity using validation loss and routing cost (Sections 3.2–3.3). Each leaf stores a precision configuration from the shared weight bank. With the tree fixed, GPU profiling selects operating points under a latency budget (Section 3.4). Online execution uses one policy call per request (Section 3.5). 3.2 LEARNING DECISION REGIONS FOR PRECISION SELECTION 

ActTune learns when to use each precision configuration from calibration errors. A binary tree partitions action context into decision regions, with one precision configuration stored at each leaf. Calibration learns the split conditions and configuration choices, while validation characterizes the tradeoff between the number of regions and routing cost. The method does not prescribe a fixed number of leaves. The tree forms xt = [ ϕ(At−1, m t−1); st] from current proprioception and the preceding predicted chunk, then selects leaf kt = g(xt) ∈ { 1, . . . , K } and configuration qt = qkt .Here ϕ extracts motion and gripper features, mt−1 is the preceding gripper margin, g(xt) is the reached leaf, and qk is its configuration (Appendix B.5). The selected number of leaves is K. These inputs are available before inference, so selection requires no additional policy call. Regions are learned from configuration losses, not predefined semantic action stages; the tree depth bounds the number of online comparisons. 3.3 ACTION -CONDITIONED PRECISION WITH SHARED RESIDENT WEIGHTS

Shared configurations. Offline calibration selects switchable matrices and their precision options under the precision and resident-storage budgets. These options form a configuration set Q; all other targeted matrices share one resident version. Each tree leaf selects a configuration, and multiple leaves may share it, so leaf count and configuration count need not match. Configurations specify resident weight versions and runtime activation precision. Calibration also determines a fallback configuration qfallback ∈ Q .

Sensitivity-guided bank construction. We calibrate layer alternatives against the BF16 check-point using activation-guided channel scaling based on activation-aware weight quantization (AWQ) (Lin et al., 2023) and output-row clipping to minimize local reconstruction error. Weighting these errors by the action Jacobian prioritizes matrices whose quantization affects action predictions more strongly. Matrices with low penalties receive fewer weight bits, freeing budget for upgrades with greater error reduction per added bit. We lower shared weight precision as needed to meet the resident-storage bound, prioritizing small error penalties per byte saved. We calibrate candidate weight/activation pairs and select a feasible bank using training action error (Appendix B.4). For each model–budget pair, one tree shares its splits and configuration indices across tasks; each index resolves to the bank associated with the task’s checkpoint.

Precision changes computation and memory traffic, shifting favorable GPU operating points (Sec-tion 2). We therefore profile frequency and power cap jointly, with the weight bank and precision selector fixed. The experiments label this joint operating-point control policy “DVFS”; its controls are requested GPU frequency and power cap. 

Offline profiling. For each supported region and configuration pair (k, q ), we measure energy and latency on training observations at operating points u = ( f, p ) ∈ U , relative to uref = ( fref , p ref ).Comparisons use the same memory frequency, observations, selector states, and random states for stochastic policies. Closed-loop measurements also include switching overhead. We retain operating points that preserve reference actions and pass memory checks. Uniform settings and a sweep over latency penalties define candidate lookup tables, each mapping a region–configuration pair to a GPU operating point. Using replay measurements, we select the table h∗ with the lowest estimated GPU energy whose mean inference latency increases by at most 10% relative to the same precision selector at uref . Unsupported pairs use calibrated fallbacks. We freeze the table, verify actions and memory on disjoint trajectories, then evaluate closed-loop task success, energy per success, and inference latency on the complete benchmark. The 10% budget applies to mean complete prediction-call latency, measured against the same frozen precision selector at the fixed reference operating point uref . Figure 5 reports this comparison for all four model–precision settings. Energy per success is total episode GPU energy, including failures and gaps between calls, divided by successes. 

Online use. After each inference, the controller predicts the next decision region and precision configuration. It looks up the corresponding GPU frequency and power cap in the frozen table and applies them asynchronously between calls. These settings remain fixed during the next inference. 3.5 ONLINE EXECUTION AND INTEGER KERNELS 

Each episode starts with empty action history and the fallback operating point. Before inference, the controller waits for any pending GPU update, traverses the frozen tree with xt, and reads qt = qg(xt).Missing history or invalid input features use qfallback . The policy produces At = πqt (ot) at the active operating point. After inference, the controller uses new action features and bounded proprioception extrapolation to forecast the next region and precision configuration. It applies the operating point from h∗ asynchronously between calls. Forecast errors leave the prepared operating point active; precision uses the current observation. Episode measurements include switching and remaining waits. Appendix A.2 gives control and runtime details. 

Executing the selected precision. ActTune executes low-bit linear layers without reconstructing dense weights. It uses INT4 ×INT4 or INT8 ×INT8 Tensor Core kernels with INT32 accumula-tion (NVIDIA, 2022). Quantization bit width determines represented values and resident weight storage; the kernel determines arithmetic operand width. Extending a code to a wider operand pre-serves its value and quantization precision. Layers whose weights and activations both use at most four bits run with INT4 arithmetic, extending two-bit codes to signed INT4 as needed. Layers with eight-bit weights or activations use INT8 arith-metic, extending narrower codes inside the kernel. W2/W4 weights for A8 layers remain packed in device memory and are sign-extended into INT8 tiles during GEMM. Together, these paths cover all nine local weight/activation pairs without changing the calibrated codes. The INT4 kernel, imple-mented in NVIDIA’s Compute Unified Device Architecture (CUDA) programming platform, uses packed operands, shape-dependent tiles, asynchronous copies, double-buffered shared memory, and fragment reuse. The INT8 Triton kernel uses coalesced weight layouts, tile-local unpacking, and software pipelining. Fusing activation quantization and GEMM epilogues for rescaling, bias addi-tion, and output conversion reduces kernel launches and intermediate memory traffic. Policy ex-ecution includes these operations; the resident-GEMM measurements in Section 2 exclude input quantization, packing, and transfers. ## 4 EXPERIMENTS 

4.1 EXPERIMENTAL SETUP 

We evaluate quantized OpenVLA-OFT (Kim et al., 2025) and π0.5 (Physical Intelligence et al., 2025) on the LIBERO Spatial, Object, Goal, and Long suites (Liu et al., 2023) (Table 1). Our hardware measurements use NVIDIA RTX A6000 GPUs. We compare ActTune with QVLA (Xu et al., 2026) and ActQuant (Akbari et al., 2026) at W4A16, and with SmoothQuant (Xiao et al., 2022), GPTQ (Frantar et al., 2022), and AWQ (Lin et al., 2023) at W4A8 and W4A4. We quantize eligible linear layers in both the vision encoder and language Transformer; other components retain their existing precision. We report task success, inference speedup, compressed-model storage, and GPU-board energy per successful episode. Appendix A.1 specifies the evaluation protocol and selector settings. Appendices A–C give hardware and controller settings, calibration details, and supplementary results. We use the average-precision budgets in Section 3.3. Two switchable matrices, each with two pre-cision options, give Q = {q00 , q 01 , q 10 , q 11 }, with qfallback = q11 . Appendix B.4 gives the selected matrices, precision options, and calibration procedure. For each model–budget pair, one tree is shared across the four LIBERO suites. ## 5 RELATED WORK 

Quantization and efficient VLA inference. Quantization and computation reuse reduce the cost of VLA inference. GPTQ and AWQ calibrate low-bit weights (Frantar et al., 2022; Lin et al., 2023), while SmoothQuant and OmniQuant address weight–activation quantization through rescal-ing and reconstruction (Xiao et al., 2022; Shao et al., 2024). For VLAs, QVLA, ActQuant, and task-evidence-aware mixed-precision quantization of VLA models (Mix-QVLA) use action sensi-tivity or task evidence to fit precision allocations (Xu et al., 2026; Akbari et al., 2026; Ranjan & Savakis, 2026); DyQ-VLA and MotionVQ adapt precision or quantized representations to motion during execution (Zheng et al., 2026; Song et al., 2026). Other approaches improve decoding and action chunking (Kim et al., 2025), reuse visual tokens or intermediate features (Xu et al., 2025; Yang et al., 2025), or overlap inference with action execution (Black et al., 2025). 

Energy-aware inference and GPU operating-point control. Energy-aware deployment must also account for hardware operation and timing constraints (Tang et al., 2019; Stojkovic et al., 2024). Hardware-aware automated quantization (HAQ) uses hardware latency and energy feedback for bit allocation (Wang et al., 2019), and PiQi combines partial quantization, processor placement, and DVFS (Aghapour et al., 2024). DynamoLLM, a system for large language model (LLM) inference, adjusts serving resources and GPU frequency under latency objectives (Stojkovic et al., 2025). For robotic workloads, saliency-aware quantized imitation learning (SQIL) studies quantized imitation policies (Park et al., 2025), while EcoVLA optimizes device-edge execution under latency con-straints (Zhou et al., 2026). We combine action-conditioned precision selection with measured GPU operating points and evaluate energy per successful episode, including failed attempts and idle inter-vals, while keeping the mean inference-latency increase within 10% of the fixed reference operating point. 

## 6 CONCLUSION 

We presented ActTune, a framework for energy-efficient VLA inference through action-aware preci-sion selection and GPU operating-point adaptation. Its decision tree learns splits and leaf configura-tions directly from configuration action errors, while hardware profiling identifies workload-specific energy–latency tradeoffs. Closed-loop LIBERO evaluation of this controller achieves 97.0% mean success for OpenVLA-OFT W4A8 and 98.4% for π0.5 W4A4. With GPU operating-point adapta-tion, ActTune reduces energy per successful task by up to 76.8% relative to the original BF16 imple-mentations, while keeping the inference-latency increase below 10% relative to the same quantized policies at the fixed reference operating point. A.7 CLOSED -LOOP LEAF -COUNT ABLATION PROTOCOL 

We test K ∈ { 1, 2, 3, 4, 6} using the calibration data and trajectory-level fitting/validation split in Appendix B. For each model–precision pair, we learn tree splits and leaf configurations directly from the four configuration losses in Equation 1, following Sections 3.2–3.3 and Appendix B.6. Loss-reducing splits grow the initial tree with maximum depth five; bottom-up pruning produces a subtree with each requested leaf count K. One tree shares its splits and configuration indices across the four suites. OFT resolves each index to the matching suite’s bank; π0.5 shares its bank across suites. Several leaves may select the same configuration. Model weights, the four-configuration banks, kernels, and fitting/validation split stay fixed across K. At K = 1 , the single leaf selects the configuration index with the lowest weighted fitting loss. At K > 1, current proprioception and previous-action features route each request to a leaf and its stored configuration. Missing history or invalid features trigger qfallback = q11 .
