Most vision-language-action (VLA) models rely on current observations and lose task-relevant evidence once it leaves view, limiting performance on long-horizon, memory-dependent tasks. Existing efforts incorporate compressed historical features or sparse visual keyframes. However, isolated snapshots can leave the policy uncertain about what changed during past interactions and which action should follow. To overcome this limitation, we propose EvoMem-VLA, which constructs state-evolution memory by explicitly encoding and retaining observed changes between historical states. These change representations preserve evidence of interaction outcomes, allowing the policy to track task progress beyond isolated snapshots. Specifically, we introduce conditional delta tokenization to encode ordered frame pairs into directional, source-conditioned delta tokens, each associated with its corresponding state evidence. A shared VLM backbone supports task-adaptive routing: normal long-horizon tasks follow a direct action route, whereas multi-stage tasks use a subtask route that generates an executable subtask as an additional input for action generation. With a single jointly trained policy for each simulation benchmark, EvoMem-VLA achieves success rates of 80.7% on RMBench, 82.0% on RoboMME and 83.8% across four real-world tasks spanning two robot embodiments. These results represent substantial improvements over the previous state of the art in all three evaluation settings.

# 1 Introduction 

Vision-language-action (VLA) models transfer pretrained visual and semantic knowledge to robot control, enabling increasingly general instruction following and manipulation across tasks (Brohan et al., 2023; Kim et al., 2024; Black et al., 2024; Zheng et al., 2025a). However, their performance remains limited on long-horizon, memory-dependent tasks. This is because a policy conditioned only on the current observation and instruction lacks access to past events that determine future actions (Koo et al., 2026; Shi et al., 2026; Yang et al., 2026a). As a result, the policy may lose track of task progress and generate an incorrect action. Recently, there have been efforts to augment VLAs with historical memory. Existing approaches represent history using discrete state features (Koo et al., 2026; Shi et al., 2026; Li et al., 2023) or sparse visual keyframes (Yang et al., 2026a; Chen et al., 2026b; Sridhar et al., 2026). However, task-relevant changes often remain implicit in the stored history (Figure 1(a)). Long-horizon control requires the policy to relate remembered states to changes during task execution. Without an explicit representation of these changes, the policy must extract them from sparse state evidence when determining task progress and selecting the next action. This motivates a memory representation that retains both what was observed and how it changed relative to an earlier observation. To address this limitation, we propose EvoMem-VLA, a state-evolution memory paradigm that explicitly encodes and retains observed interaction changes between sparse historical observations (Figure 1(b)). By linking change representations to corresponding visual states, this memory preserves evidence of interaction changes. Specifically, to explicitly represent the visual change from the source frame to the target frame, we introduce conditional delta tokenization (Kerssies et al., 2026) to encode ordered frame pairs sampled from recent observations and selected keyframes into delta tokens. We then construct state-evolution memory by arranging these delta tokens alongside the initial frame, recent historical frames, and selected keyframes (Yang et al., 2026a) in temporal order. Next, the state-evolution memory is fed into a shared VLM backbone together with the task instruction and current observation. Additionally, the VLM backbone supports task-adaptive routing: for normal long-horizon tasks without multi-stage planning, it predicts actions directly; for multi-stage tasks, it first generates an executable subtask and then appends it to the original input context to guide action generation (Yang et al., 2026c). Our contributions are summarized as follows: 1. We propose EvoMem-VLA, a state-evolution memory paradigm that explicitly retains observed interac-tion changes alongside historical states. # 2 Related Work  

> Vision-Language-Action Models.

Vision-language-action (VLA) models adapt pretrained vision-language representations to language-conditioned robot control (Qu et al., 2025; Shukor et al., 2025). RT-2 and OpenVLA formulate action generation as autoregressive prediction over discretized action tokens (Brohan et al., 2023; Kim et al., 2024). More recent approaches introduce continuous or hybrid action generation (Kim et al., 2025): π0 uses a flow-matching action expert (Black et al., 2024), CogACT and DexVLA condition diffusion-based action experts on VLM features (Li et al., 2024; Wen et al., 2025), and HybridVLA combines autoregressive prediction with diffusion action generation (Liu et al., 2025). X-VLA studies policy scaling across heterogeneous robot embodiments (Zheng et al., 2025a). Despite advances in action representation and policy scaling, these models do not inherently maintain a persistent record of task execution. When earlier evidence leaves the observation window, a policy may lose track of what it has observed or completed, even when this history is needed to disambiguate visually similar states requiring different actions.  

> Memory Augmented Vision-Language-Action Models.

History-aware policies address this limitation by retaining or transforming past observations (Zhang et al., 2025; Ni et al., 2025; Fang et al., 2025; Torne et al., 2026). RoboFlamingo compresses temporal vision-language features into an LSTM policy state (Li et al., 2023), while TraceVLA overlays tracked point trajectories on current images as visual motion prompts (Zheng et al., 2025b). HAMLET encodes observations as temporally discriminative moment tokens and aggregates them through a lightweight causal memory module (Koo et al., 2026). MemoryVLA maintains perceptual and cognitive representations in long-term memory and retrieves relevant entries for action prediction (Shi et al., 2026). EventVLA retains the initial observation and a recent history window alongside event-triggered keyframes in bounded memory (Yang et al., 2026a). MemER uses a high-level policy to select and consolidate keyframes, predict the current language subtask, and delegate execution to a separate low-level controller (Sridhar et al., 2026). Complementary approaches use language and reasoning to guide action generation (Zawalski et al., 2024; Belkhale et al., 2024; Huang et al., 2025): on multi-subtask data, π0.5 predicts a semantic subtask before generating the corresponding action chunk (Physical Intelligence et al., 2025), while WLA-0 jointly learns textual-subtask prediction, future-state prediction, and action synthesis (Yang et al., 2026c). These methods provide remembered states, motion cues, and subtask context through distinct interfaces. However, the cited state-oriented memories lack dedicated inter-state change representations, while TraceVLA’s short-window motion traces are not integrated with sparse long-term state evidence. MemER provides history to its high-level policy, but its controller receives only the predicted subtask, current images, and robot state. In contrast, EvoMem-VLA organizes multi-scale visual states and learned inter-state changes in state-evolution memory shared by subtask and action prediction. Tasks without textual-subtask supervision retain a direct action route through the same VLA policy. 

# 3 Method 

EvoMem-VLA constructs state-evolution memory by organizing initial, recent, and selected keyframe obser-vations alongside delta tokens that explicitly encode observed changes between frames. At each replanning step, a shared VLM backbone takes this memory, the current observation, and the task instruction as input and supports task-adaptive routing. For tasks without multi-stage planning, it predicts actions directly; for multi-stage tasks, it first generates an executable subtask and appends it to the input context to guide action generation. A lightweight Keyframe Head selects task-relevant observations to update the keyframe memory online. Figure 2 summarizes the architecture.

> Conditional Delta Tokenization.

Given an ordered source–target image pair (Iu, Iv ) with u ≤ v, the frozen DINOv3 encoder ϕ (Siméoni et al., 2025) produces patch features fu = ϕ(Iu) and fv = ϕ(Iv ). Following conditional feature compression in video (Kerssies et al., 2026), a paired-frame encoder g∆ compresses the target information not explained by the source into a single token: 

zu→v = g∆(fu, fv ; q∆), (2) where q∆ is a learned query. A decoder reconstructs bfv = h∆(fu, zu→v ), and the tokenizer is pretrained with 

L∆, the log-cosh reconstruction loss averaged over patches and feature dimensions. This bottleneck yields a directional, source-conditioned change token rather than a pixel difference, optical-flow field, or action code. After pretraining, the DINOv3 encoder ϕ and g∆ are frozen, h∆ is discarded, and only the delta tokens are used by the VLA.

3.3 Task-Adaptive Routing 

For tasks with temporally grounded subtask supervision (Yang et al., 2026c), EvoMem-VLA makes the current execution stage explicit. Let st be the annotated subtask text for the action window, Rt the prior subtask text, and Ct = [ Mt; L; Eℓ(Rt)] . The subtask route is 

bst = Decode θ (Ct), bAt = Π θ,ψ ([ Ct; Eℓ(bst)]) . (5)  

> Subtask-conditioned route.

Decode θ uses the shared backbone and language-modeling head to generate the executable subtask. The generated text is appended to the same state–change context for a second backbone pass and action prediction. During training, Rt comes from preceding subtask annotations; during rollout, it accumulates generated subtask text, skipping empty outputs and consecutive duplicates, and is reset at each episode. It records prior predictions, not verified task completion. Temporally aligned labels can repeat across calls or include consecutive descriptions within a window; the language end token only terminates text decoding. 5Direct route. Task-adaptive routing is specified by task-level configuration rather than a learned complexity classifier. On the direct route, Rt is empty and bAt = Π θ,ψ (Ct). Both routes share the visual encoder, delta projection, VLM backbone, action queries, action head, and Keyframe Head; semantic supervision changes only the conditional path. 

3.4 Learning and Closed-Loop Inference  

> Two-stage optimization.

Training separates change representation learning from policy learning. Stage 1 trains g∆ and h∆ on ordered frame pairs with ϕ frozen. Stage 2 freezes ϕ and g∆ and optimizes the VLA, action head, delta projection, and Keyframe Head on robot demonstrations using 

L = Lact + λlang Llang + λkf Lkf . (6) The weights λlang and λkf balance language and keyframe supervision. Lact is applied to every sample. Llang 

is token-level cross-entropy over target subtask positions, with visual inputs, prompts, and action queries masked; direct-route samples contribute zero language loss. Lkf is positive-weighted binary cross-entropy over supervised offsets and is zero without valid keyframe supervision. Each term is normalized over its valid elements before weighting. Subtask-route action training uses ground-truth subtask text, whereas deployment uses generated text. Because the tokenizer is frozen in Stage 2, L∆ is excluded from Equation 6.  

> Closed-loop inference.

At each replanning step, the policy reads the fixed anchors, current observation, and committed event states; encodes the three recent delta groups and event-local delta tokens; and assembles 

Mt as in Equation 3. The configured route then predicts an action chunk directly or generates and feeds back a subtask before action prediction. The Keyframe Head may concurrently schedule a future capture, which is written only when its timestamp is reached. The recent cache, bounded event-state bank, and enabled subtask history are then updated. This read–infer–act–write loop conditions every prediction only on evidence already observed by the robot. 

# 4 Experiments 

4.1 Experimental Setup  

> Simulation setup.

We evaluate EvoMem-VLA on two memory-dependent simulation benchmarks. RM-Bench (Chen et al., 2026a) comprises nine bimanual manipulation tasks, including five M (1) tasks and four 

M (n) tasks. Here, M (1) tasks require retaining a single task-relevant past observation, whereas M (n) tasks require information from multiple past observations. RoboMME (Dai et al., 2026) contains 16 tasks that eval-uate counting, permanence, reference, and imitation memory. We implement EvoMem-VLA in the QwenOFT framework (StarVLA Community, 2026) and initialize the shared backbone from Qwen3-VL-4B-Instruct .For each benchmark, we jointly train a single policy across all tasks and evaluate 100 episodes per task; RoboMME uses 50 easy, 25 medium, and 25 hard episodes per task.  

> Real-world setup.

We evaluate four tasks using a Franka single-arm robot and an AgileX COBOT dual-arm platform. We initialize the shared backbone from the robot-pretrained VLAct checkpoint (Yang et al., 2026b) ( StarVLA/VLAct_Qwen3_Pretrain ) and train a separate policy for each embodiment. Each robot is evaluated on 10 episodes per task: 40 per embodiment and 80 in total. We report per-task success rates pooled across embodiments and their unweighted average. Camera layouts are shown in Figure 5 (Appendix A.5).  

> Compared baselines.

For simulation, we compare against memory-free policies, including Diffusion Policy (DP) (Chi et al., 2025), ACT (Zhao et al., 2023), π0.5 (Physical Intelligence et al., 2025), X-VLA (Zheng et al., 2025a), and QwenOFT; and memory-augmented policies, including MemER (Sridhar et al., 2026), Mem-0 (Chen et al., 2026a), MemoryVLA (Shi et al., 2026), and EventVLA (Yang et al., 2026a). 4.2 Simulation Results 

Results on RMBench. Table 1 reports task-level and aggregate success rates on RMBench. A single EvoMem-VLA policy jointly trained across all nine tasks achieves an overall success rate of 80.7%, exceeding the previous best full-benchmark result of 67.8% from EventVLA by 12.9 percentage points. EvoMem-VLA obtains 84.0% on the M (1) tasks and 76.5% on the more demanding M (n) subset. On M (n), the jointly trained policy exceeds EventVLA’s 54.0% by 22.5 percentage points. At the task level, EvoMem-VLA ranks first or second on every task, reaching 100.0% on Rearrange Blocks , Swap Blocks , and Swap T , and 96.0% on both Blocks Ranking Try and Cover Blocks . The largest gain over EventVLA occurs on Press Button ,where the success rate rises from 3.0% to 70.0%. The stronger improvement on M (n) is consistent with the intended role of state-evolution memory and subtask conditioning in tracking progress through repeated and multi-stage interactions, while the M (1) results show that the same jointly trained policy remains effective on tasks with simpler memory structure. 

Results on RoboMME. Table 2 compares success rates across the four memory categories of RoboMME. A single EvoMem-VLA policy jointly trained across all 16 tasks achieves an overall success rate of 82.0%, outperforming FrameSamp (Modul), the strongest baseline in the table at 44.5%, by 37.5 percentage points, and MemER at 42.4% by 39.6 points. EvoMem-VLA leads the compared baselines in every category, achieving 786.5% on counting, 88.5% on permanence, 74.5% on reference, and 78.5% on imitation. These results show consistent gains across all four evaluated memory capabilities.

As shown in Figure 3, EvoMem-VLA achieves 83.8% overall success, compared with 30.0% for πMEM and 5.0% for π0.5, and leads both baselines on all four tasks. Lift Cup tests repetition counting (85.0%), Cover Ducks 

tests object-identity memory under occlusion (90.0%), Route Recall tests memory for demonstrated spatial order (75.0%), and Put Back Cup tests recall of an object’s original location after displacement (85.0%). These tasks require different uses of interaction history. In Lift Cup , the cup returns to a similar pose after each repetition, so its current position does not indicate how many lifts remain. Cover Ducks requires remembering duck identities after they are covered, whereas Route Recall requires retaining the order of a transient pointing demonstration, including repeated visits, and tracking which placements are complete. In Put Back Cup , the shared intermediate position no longer identifies the original box. Together with the RMBench ablations, these results support conditional delta tokenization as an effective way to preserve interaction-progress evidence alongside historical states for robot control. 

4.4 Ablation Study  

> Effect of conditional delta tokenization.

Removing delta tokens lowers success on both M (1) (84.0% to 59.0%) and M (n) (76.5% to 44.0%). > Complementary role of subtask conditioning.

As shown in Table 3, removing subtask routing leaves M (1)

> Qualitative trajectory comparison.

In the Press Button episode in Figure 4, the instruction requires pressing the left button nine times, the middle button once, and finally the rightmost termination button. Repeated presses leave visually similar states, so the policy must remember the completed press count to decide when to switch buttons. Under the same initialization, EvoMem-VLA completes this sequence, whereas the variant without delta tokens follows an incorrect trajectory and returns to the left button. The naive feature difference variant reaches the middle button but presses it repeatedly instead of proceeding to termination. These trajectories illustrate how conditional delta tokens preserve the interaction-progress evidence needed to select the appropriate next action. 95 Conclusion 

In this paper, we presented EvoMem-VLA, a state-evolution memory paradigm that explicitly retains observed interaction changes alongside historical states for action generation. Our unified VLA uses conditional delta tokenization to construct multi-scale state-evolution memory and supports direct or subtask-conditioned action generation through task-adaptive routing. Experiments on RMBench, RoboMME, and four real-world tasks across two robot embodiments demonstrate improvements over the previous state of the art. RMBench ablations further validate the central contribution of conditional delta tokenization.

12 A Implementation and Training Details 

A.1 Policy Architecture and Initialization 

We implement EvoMem-VLA using the QwenOFT framework in StarVLA (StarVLA Community, 2026). Simulation policies are initialized from Qwen3-VL-4B-Instruct , with one policy jointly trained across all tasks in each benchmark. For real-world experiments, we initialize from the robot-pretrained StarVLA/VLAct_-Qwen3_Pretrain checkpoint (Yang et al., 2026b) and train one policy per embodiment. The continuous action head is a residual MLP with two residual blocks and a hidden width twice that of the VLM. A learned linear layer maps delta tokens into the VLM embedding space. Subtask generation uses the backbone’s language-modeling head, and route selection is specified by the task configuration.  

> Simulation route assignments.

RMBench uses the direct route for its five M (1) tasks and the subtask-conditioned route for its four M (n) tasks (Battery Try, Blocks Ranking Try, Cover Blocks, and Press Button). All 16 RoboMME tasks use the subtask-conditioned route. These assignments remain fixed during training and evaluation.  

> Supervision and alignment.

RMBench uses episode-level subtask text segments aligned by frame index: preceding segments form the history, and segments overlapping the current action window supply the target text. RoboMME uses its native subgoal text and subgoal-boundary annotations for subtask and keyframe supervision, aligned with observations and actions by episode timestep. The current subgoal supplies the text target, while earlier subgoals form the history. These labels are used during training; deployment uses model-generated subtasks and keyframe predictions. 

A.2 Delta Tokenizer Training 

The Delta Tokenizer follows DeltaTok (Kerssies et al., 2026) and extracts patch features with frozen DI-NOv3 (Siméoni et al., 2025). For simulation, we initialize from the released DeltaTok weights and adapt a separate tokenizer on each benchmark’s demonstration dataset. Source and target images come from the same camera stream, separated by 15 observation steps. The encoder compresses each pair into one delta token, and the decoder reconstructs the target features conditioned on the source features and this token. Only the tokenizer encoder and decoder are updated, using the mean log-cosh reconstruction loss; DINOv3 remains frozen. Table 4 summarizes the shared implementation and optimization settings. Frame pairs are sampled within demonstration episodes, never across episode boundaries. RoboMME adaptation uses the same released demonstration episodes as policy training, with task-balanced sampling. Tokenizer adaptation is completed before policy training; the 80,000-step policy budget does not include tokenizer updates. Real-world experiments use the official pretrained DeltaTok checkpoint directly, without task-specific tokenizer adaptation. During policy training and deployment, both DINOv3 and the Delta Tokenizer remain frozen, and the reconstruction decoder is discarded. 

A.3 Simulation Policy Training 

Table 5 summarizes policy training on RMBench and RoboMME. Both benchmarks use an 80,000-step training budget with eight GPUs, a per-GPU batch size of four, and no gradient accumulation. We use AdamW with 

β = (0 .9, 0.95) and ϵ = 10 −8. The learning rate follows a cosine schedule after 5,000 warmup steps, with a minimum learning rate of 5 × 10 −7. The backbone, delta projection, and action head are trained while the change representation remains frozen. All samples supervise action prediction. Subtask-route samples additionally supervise the annotated subtask text with a language-loss weight of 0.005 ; direct-route samples contribute no language loss. Action training uses the annotated subtask, whereas deployment uses the generated subtask. On RoboMME, the Keyframe Head is trained with positive-weighted binary cross-entropy, using a positive-class weight of 7 and a keyframe-loss weight of 1. A.4 Memory Construction and Episode Boundaries 

The three recent delta-token groups encode (t − 45 , t − 30) , (t − 30 , t − 15) , and (t − 15 , t ), respectively, with one token per camera stream. The initial frame is retained separately as a visual anchor. Negative indices are clamped to zero, reusing the initial frame at the beginning of an episode. Frames used only as tokenizer sources are not added as extra RGB memory entries. RMBench uses the initial and recent observations together with these three delta-token groups; keyframe memory is disabled. RoboMME additionally retains up to 16 keyframes, each paired with a primary-view delta token computed from the observation 15 steps earlier. Its Keyframe Head schedules a recording when the predicted probability exceeds 0.55. The observation is stored only when its scheduled capture time is reached, and capacity overflow removes the oldest record. A.5 Real-World Training and Deployment 

We use a Franka single-arm robot and an AgileX COBOT dual-arm platform. Figure 5 shows their camera configurations. The Franka setup provides one main-view camera and one wrist camera; the AgileX COBOT setup provides one main-view camera and two wrist cameras, one for each arm. We collect 50 demonstrations per task for each embodiment, yielding 200 demonstrations per embodiment and 400 in total across the four tasks. Each embodiment has a separately trained policy initialized as described in Appendix A.1. We fine-tune all VLA policy parameters while keeping DINOv3 and the official pretrained Delta Tokenizer frozen. Both embodiments use the same optimization settings, following the real-world training configuration of EventVLA (Yang et al., 2026a). Specifically, we use AdamW for 60,000 optimization steps with a global batch size of 32 and a peak learning rate of 5 × 10 −5. After 2,000 warmup steps, the learning rate follows a cosine decay schedule to 5 × 10 −6. Table 6 summarizes the training and deployment settings. At each replanning step, the policy predicts an action chunk of 30 steps and executes its first 16 steps before replanning. Keyframe memory is enabled with a capacity of five frames, alongside the initial and recent observations and three recent delta-token groups.
